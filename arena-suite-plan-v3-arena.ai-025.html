Architecture & implementation plan · private single-user macOS app

Arena Local Archivedeep-capture conversation archive for arena.ai

A permanent-private macOS application that embeds its own browser engine, signs the owner into multiple arena.ai accounts simultaneously in isolated partitions, records complete local transcripts with provenance, and exposes every capability to an LLM through a local MCP server.

Target Apple Silicon arm64 Declared macOS floor 13.0 Ventura Dev machine M3 Pro / 18 GB / macOS 27 Primary interface MCP (stdio) Distribution none

Selected architecture

A dedicated Electron application (Chromium, arm64) whose privileged main process owns one isolated Chromium session partition per arena.ai account, and captures through browser-process network filtering plus in-process Chrome DevTools Protocol — not through page-world interception.

Eligible under the constraints: it is not a browser extension, not a chrome.debugger extension, not extension+host, and not extension+companion. The existing Manifest V3 exporter is treated only as a measured baseline.

Why this one

  • Capture happens where an extension cannot reach: the browser process sees every request in a partition — including requests made by workers and service workers — and CDP can retrieve response bodies, which chrome.webRequest never exposes.
  • One engine, one language. Session partitioning, CDP, net.request with the account's own cookies, and app-owned downloads are all first-class documented APIs in the same TypeScript codebase an AI agent maintains.
  • The arena.ai page itself needs zero injected code to be captured. No content script, no monkey-patched fetch as the primary path, no extension lifecycle to lose the stream.

What would reverse it

If Gate G1 shows Electron's bundled Chromium cannot (a) attach CDP early enough to retain bodies across navigation, or (b) reach worker / service-worker targets, escalate to CEF with a C++ GetResourceResponseFilter — see §3.4. CEF is deeper; it is rejected on maintenance cost, not capability.

1.2 The one-sentence justification

An MV3 extension observes arena.ai from inside the page's security context; this app observes it from outside every page context, which is the difference between "the page happened to route its traffic through a fetch we patched" and "the browser process saw the request and its body regardless of who initiated it".

1.3 What is still page-dependent — stated plainly, because the prompt asks for it

This architecture is not purely out-of-band. Concretely:

  • Primary network capture is out-of-band. session.webRequest and CDP Network/Fetch domains run in privileged processes. No monkey-patching is required to obtain request metadata, headers, bodies, SSE messages, or WebSocket frames.
  • Rendered-page state is page-world. Vote state, blind labels, revealed model names, participant ordering and "stop / rerun" affordances are read with Runtime.evaluate over CDP and, where a mutation observer is genuinely needed, with Page.addScriptToEvaluateOnNewDocument. This layer is explicitly labelled L3 and is a complement, never the primary capture path. It is also the layer most exposed to the A/B-tested UI described in §2.1.
  • Service-worker observability is the open question. See §4.2 and Gate G1; the fallback is documented and has a known capability cost.

3.3 Tauri/Wry and native WKWebView — rejected on capture, not on quality

Both are excellent macOS shells. Neither offers a documented path to response bodies, and macOS has no DevTools Protocol for WebKit. SI Everything meaningful — SSE deltas, WS frames, subresource traffic, service-worker fetches — would have to be recovered by patching the page, which is the exact failure mode this project exists to escape. A WebKit shell is also a second engine next to Safari on the same machine, which is the opposite of "avoid duplicated browser engines".

5.3 Text coverage for the first complete release

The v1 text release must represent, without flattening:

  • Modes: battle, direct-model, side-by-side. Mode is an explicit field on the conversation, sourced from the request/response, not inferred from the number of visible panes (recall remove-side-by-side in Table 3).
  • Completion states per turn: completed, stopped, failed, partial — plus unknown-missed for the observer's own failure. These are four different things and are never collapsed.
  • Conversations opened from history: search result, paginated list, archived-history view. The opened_from provenance field records which surface produced the navigation, because the same conversation reached three ways must still be one record per account.
  • Identity evidence: selected model labels, blind participant labels, visible votes, post-vote reveal events. All append-only; see §7.2.
  • Structure: title, timestamps, source ids, branches, revisions/regenerations, participant positions, completion state — each an explicit column, not a convention in a text blob.
  • Account/session scope on every observation, as part of record identity.

The promotion rule. unknown-missed and body-unavailable are terminal-for-now states. Nothing in the system may promote them to complete except a successful re-fetch through L5 or a new observation that carries genuine end-of-stream evidence. There is no heuristic that infers "the response probably finished". A stopped turn is stopped, never finished; a transport failure is transport-failed, never stopped; an observer miss is unknown-missed, never partial. This rule is enforced by a check that runs in CI against fixtures (Gate G2).

6.2 Access characterisation, stated precisely

Three mechanisms the prompt asks to be kept distinct, applied to this app:

  • Authenticated read access. Replaying an owner-history read from inside the account's own partition, with the session arena.ai itself issued to that partition, is authenticated read access to the owner's own data. That the endpoint is undocumented or internal changes nothing about its access control: the control is the account-scoped session, and the app holds exactly the session the owner established.
  • Automation compatibility. The app presents a normal browser: no --disable-blink-features=AutomationControlled-style masking is used, no UA spoofing, no fingerprint alteration, no automation-controlled flags exposed to the page. If arena.ai's reCAPTCHA Enterprise or Cloudflare scoring (Table 3 rows 2–3) produces a challenge, the app pauses and shows the owner the challenge in the real window. Masking would be both a maintenance liability and a signal-avoidance tactic the app deliberately does not take.
  • Access-control workarounds. None are used or planned. There is no client-side restriction being circumvented, no capability escalation, no enumeration of infrastructure the owner does not own. If a required operation ever turned out to require one, that operation would be dropped and recorded as a coverage gap — it is a stop condition, not a technique.
No credential copying, ever. Replay reuses the session in place via useSessionCookies:true. The app never extracts a cookie or token to a file, a variable, a log line, a fixture, or an export. Browser-managed persistence (Chromium's own on-disk cookie store, encrypted with a Keychain-held key) is the only credential store, and it is never read by the app. This is stated as an invariant because it is the difference between "reusing my session" and "handling my credentials".

Auth expiry / account changeDetected by 401/403, a redirect to /auth, or a server-observed identity that no longer matches the partition's last known identity. Effect: pause that account, surface it, keep all others running. The app never attempts to refresh by reading cookies. A refresh is the browser's own behaviour.
Drift, redirects, challenges, suspected mutationSchema drift → pause, keep the raw evidence, raise a drift event with the shape hash before/after. Unexpected redirect → pause that account. Unresolved challenge → pause that account and open the window so the owner can complete it. Any operation classified mutation appearing during a sync pass → immediate pause of that account's sync, full stop, drift event; the pass is not retried automatically.
Cross-account id collisionsThe same conversation id observed under two accounts produces two records and one conflict(account_a, account_b, kind='source-id-collision'). It is never merged, never resolved heuristically, and is surfaced in diagnostics until a human annotates it.
What "synchronized" meansStated per account in sync_checkpoint.state='done' plus an enumerated residual-gap list. An agent reads both via arena.sync.status and arena.diagnostics.gaps.
If no reliable listing endpoint, stable pagination, or complete history representation can be verified. Then: history is reconstructed by hidden-window traversal of whatever list surface Arena renders, with every page recorded as an op_evidence row so the traversal itself is auditable; completeness becomes explicitly unknown rather than done; and the archive is honest that it is "everything the owner has scrolled past and the app observed", not "the account's full history". Live capture remains fully functional and unaffected. This degradation is a declared, visible state — not a silent failure and not a fake complete.

07Data, identity, provenance, protection

A proportionate source of truth: normalised records with an append-only observation stream behind them. Not full event sourcing.

7.1 Representation and source of truth

REC Hybrid, deliberately small: normalised records are the query surface; append-only observations (identity, source, capture) carry provenance; encrypted raw artifacts hold large binaries. There is no generic event log, no projector framework, and no CQRS. The reason is proportionality: this is one user, one machine, and the expensive questions ("what did the archive observe, and how sure is it?") are answered by a handful of observation tables, not by replaying an event stream.

What is not the source of truth: sanitized evidence rows. They exist to diagnose drift and to support re-parsing, they are retained for a bounded window (default 90 days), and an adapter change can recompute normalised rows from them while they last. After retention expires, the normalised rows stand alone. This trade-off is explicit rather than accidental: full event sourcing would make every historical reparse possible forever, at the cost of an unbounded encrypted store and a replay system — unjustified here.

Transaction boundaries, crash recovery, migration, backup

  • Transactions. One SQLite transaction per normalisation unit: a turn plus its source observations plus its identity observations plus the affected conversation's capture_state recomputation. Evidence rows are written before the transaction that consumes them, so a crash leaves an unreferenced evidence row (harmless, garbage-collected) rather than a normalised row with no provenance.
  • Crash recovery. WAL mode; on boot, a recovery pass closes every CaptureSession and SyncJob left running, writing unknown-missed for any turn without end evidence. Nothing is promoted to complete by recovery.
  • Migration. Drizzle-managed, forward-only, each migration a no-op-if-already-applied transaction; schema_migrations row is written in the same transaction as the DDL. A migration failure leaves the DB at the previous version, never half-migrated.
  • Backup/restore. VACUUM INTO produces a single encrypted file; artifacts are restored from their blob directory. Restore verifies record counts against an export_manifest. Time Machine covers the whole container — ciphertext for the DB and blobs, so a backup is not a plaintext leak, but a backup is also not a portable secret: the Keychain key does not travel with the backup.
  • Deletion interaction. See §7.5.

8.5 The guard against content-driven destructive actions

Archived prompts, responses, tool traces and diagnostic text are untrusted data. They are never operational authority. The mechanism is not "be careful"; it is a token the data cannot produce.

// 1. READ-ONLY PREVIEW — safe to call from anywhere, including an agent reading transcripts.
arena.delete.preview { scope_type:'account', scope_id:'acct-a' }
  → {
      would_delete: { conversations: 412, turns: 3180, artifacts: 37,
                      bytes: 184_223_991, accounts_untouched: ['acct-b'] },
      scope_token:  'st_7f3c…',          // HMAC(scope, nonce, per-process key), TTL 5 min
      scope_digest: 'sha256:9ab1…',      // bound to the exact scope shown to the user
      expires_at:   '…'
    }

// 2. DESTRUCTIVE CALL — requires the token. No other path exists.
arena.delete.account_data { scope_token:'st_7f3c…' }
  → rejects if: token missing · expired · scope mismatch · scope != account · nonce reused

// 3. ARCHIVE-WIDE — additionally requires the owner's typed phrase, via the GUI.
arena.delete.archive { scope_token:'st_…', confirm_phrase:'DELETE THE ENTIRE ARCHIVE' }
Table 24 — Why retrieved content cannot authorise deletion.
PropertyGuarantee

Nonce reuseEach token is single-use. A replay of a successful deletion is rejected.

09Local analysis and later modalities

Deterministic statistics first, cohorts built only from observed or revealed identity, uncertainty preserved end to end.

9.1 Initial model profiles

REC v1 analysis is transparent deterministic statistics in TypeScript on a worker thread. No embeddings, no local model, no GPU work. The justification is not laziness: for the questions this archive exists to answer ("how does this model's prose behave, and how stable is that behaviour across prompt types?"), deterministic statistics are inspectable, reproducible to the byte, and cheap enough to recompute on every adapter change. Embeddings would add packaging cost, weight-pinning obligations, preprocessing versioning and offline-setup complexity to answer a different question, and that question is not on the critical path.

9.2 Later similarity and fingerprinting experiments

REC These are hypothesis tests, not identification. Similarity to an archived corpus is a confidence-qualified hypothesis about stylistic resemblance. It is never proof of model identity or authorship, and inferred identity is stored in a field that is visibly separate from observed identity.

Table 27 — Predeclared empirical criteria for any similarity experiment.

12.3 Minimum macOS version

REC macOS 13.0 Ventura is the app's declared minimum.

The basis is narrow and stated: the Electron release line current at the time of writing declares "macOS (Ventura and up)" for its 64-bit Intel and Apple-Silicon binaries VF. Nothing else in the app requires a newer API — the Keychain usage, hardened-runtime entitlements, URLSession-free Node stack and arm64-only slice are all Ventura-compatible. Consequently:

  • The floor moves only when Electron's floor moves, and only after a deliberate review.
  • Ship an arm64-only slice, not universal. The target is Apple Silicon; a universal build doubles download and app size for a machine that will never run the x64 half, and would pull in Rosetta-adjacent risk for no benefit.
  • The owner's machine (M3 Pro, 18 GB, macOS 27) is well above the floor; the floor exists to make the constraint explicit and to avoid accidentally depending on a newer API during implementation.
  • Development machine requirement is macOS 12 or newer per Electron's own build instructions, which is satisfied.

12.4 What an implementing agent should do first

  1. Build the G0 spike: two partitions, two windows, owner-driven sign-in, identity read back from the server-rendered payload, and the positive isolation precondition (two distinct signed-in identities) before any leakage assertion.
  2. Build the G1 spike as a falsification harness: late attach, navigation mid-stream, worker/SW attach, streamed body, partial/stopped/failed, downloads, two-account concurrency. Record outcomes as data, including failures.
  3. Only then build the smallest vertical slice of §5.6. Do not build the archive workspace, the analysis profiles, or any modality beyond text until that slice returns a real transcript with a real body_sha256.
  4. Generate the GUI command list and the MCP tool list from one source, and keep the equality test in CI from the first commit.
