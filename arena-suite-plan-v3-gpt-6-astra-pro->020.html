Private Arena Conversation Archive for macOS

A dedicated-browser, owner-session, offline-first archive for your own arena.ai conversations (Battle, Direct, Side-by-Side, Code/Agent surfaces). Minimal diagnostics-first GUI. Local MCP server is the primary interface. Apple Silicon only. No distribution, no hosted backend, no telemetry, no multi-user support.

Deliverable: arena-model-archive-plan.html (this file). No application code was implemented. Small schemas / pseudocode / protocol sketches are illustrative. Evidence labels are used throughout; unperformed work is never presented as completed.

0 · Verdict — read this first

RECOMMENDATION ELIGIBLE DEDICATED BROWSER REVERSIBLE ON DEFINED TRIGGER

Build an Electron/Chromium dedicated browser app (TypeScript + Node, one bundled Chromium, per-account session.fromPartition), with main-process CDP capture (webContents.debugger + Target.setAutoAttach + Network/Fetch) as the primary observation path, a thin page-world reconciler as secondary, SQLCipher + Keychain store, and a localhost MCP server (Streamable HTTP + stdio) as the primary interface.

Why this stack wins

  • Deeper than the extension baseline in the exact failure areas: browser-process network tap sees chunked streams, worker/service-worker targets, early-navigation and late-attach traffic that page-world fetch monkey-patching misses.
  • Simultaneous isolated accounts: persist:arena-acct-<uuid> partitions isolate cookies, storage, cache, service workers per account — WebKit shells cannot match this with documented APIs.
  • Direct downloads/artifacts: will-download + app-owned save path; no chrome.downloads sandbox or companion bridge.
  • Agent-operable: one language (TS), one engine, reproducible Forge builds, structured NDJSON diagnostics, machine-checkable gates.

What would force a change

  • Trigger T1 (capture): if the falsification spike (§10 Gate B) shows Electron CDP still misses >1% of streamed bytes or worker frames that CEF CefResponseFilter reliably captures on the same workflows → pivot browser layer to CEF, keep store/MCP/analysis unchanged.
  • Trigger T2 (auth): if Arena email flow requires a capability Electron cannot present (e.g., OS-bound passkey — out of scope — or persistent third-party IdP popup the app blocks) → fix by relaxing popup/permissions policy first, not by switching stacks.
  • Trigger T3 (maintenance): if Electron drops required CDP domains or arm64 macOS support → escalate to CEF, then custom Chromium fork (last resort only).

Minimum OS: macOS 14.0 Sonoma, arm64 only (see §2). Fallback: CEF + Node sidecar (§4.6). Explicitly rejected as primary: MV3 extension / chrome.debugger extension / extension+native-host / companion bridge; WKWebView / Tauri; export/import-only.

2 · Product & operating context

Scope (fixed)

  • Permanently private, single human owner, own Arena accounts only. No distribution, sale, App Store, hosted backend, multi-user, app-account, telemetry, cloud analytics, public updater.
  • Simultaneous multi-account: ≥2 Arena sessions active at once with isolated cookies, storage, cache, service-worker state, capture state, sync state, provenance, destructive-action scope. Failure/sign-out in one must not invalidate, corrupt, or silently rebind another.
  • Heavy usage; no archive size assumed. §8 quotas + §11 measurements define limits empirically.
  • AI agents implement/operate/troubleshoot. Mainstream deps, reproducible setup, structured diagnostics, autonomous checks.
  • v1 GUI minimal + diagnostics-first. MCP (or justified equivalent) is primary; every GUI capability exists on MCP with identical semantics.
  • Workflow: sign in + use Arena inside the app via Arena's own flows. Email sign-in sufficient; Google/OAuth/passkeys must not disqualify a stack. Owner-driven verification codes / MFA / CAPTCHA / redirects / popups must be completable.

Platform (fixed)

  • Host: M3 Pro, 18 GB unified memory, macOS 27 (present machine).
  • Recommendation Minimum: macOS 14.0 Sonoma, arm64 only. Rationale: lets the app track a maintained Electron/Chromium + Xcode SDK + safeStorage/Keychain behavior while refusing Rosetta/x86_64 and pre-Sonoma WebKit/SDK variance. Build matrix tests 14/15/26/27 arm64; installer refuses x86_64 with a clear message. If the capture spike needs a newer SDK API, raise the floor to 15.0 explicitly — never silently.
  • Avoid resident runtimes + duplicated engines: exactly one bundled Chromium (via Electron); no system-Chrome dependency; no second engine for analysis; Python only as an optional pinned analysis venv, never resident.
  • Nothing assumed installed. Setup installs: Xcode CLT, Node LTS (via fnm/volto), Electron Forge deps. No public packaging optimized; local .app + signed-dev run is the target.

Hard boundaries (enforced in code + MCP)

  • Only data of currently signed-in app-owned accounts; every op carries accountId + partitionId. URL/ID alone never proves ownership. No cross-browser/app cookie import, no credential guessing, no unrelated-infra enumeration. Never merge across accounts on similar IDs/titles/text/timestamps — collisions become explicit ownership_conflict records.
  • Arena controls auth. Sync may transiently reuse session-issued credentials (incl. refresh) in memory only; never persist to disk, exports, fixtures, logs. Browser-managed persistence (cookies/storage) lives in the partition, protected per §8, isolated per account.
  • Visible pause/cancel/stop per account + globally; effects on in-flight work defined (§6–7, §9).
  • Safe degradation per affected account on sign-out, mismatch, lost authority, ambiguous ownership, unsupported navigation, observer failure, schema drift, rate limit, challenge, redirect, suspected mutation. Other accounts continue.

5.3 Session / partition model (simultaneous accounts)

// illustrative — partition per account, never shared
import { session, BrowserWindow } from 'electron';
function windowForAccount(accountUuid: string) {
  const part = `persist:arena-acct-${accountUuid}`; // stable per account
  const ses = session.fromPartition(part);          // cookies·storage·cache·SW isolated
  ses.setPermissionRequestHandler(/* deny-by-default */);
  const win = new BrowserWindow({ show: true, webPreferences: {
    session: ses, sandbox: true, contextIsolation: true,
    nodeIntegration: false, nodeIntegrationInWorker: false } });
  win.webContents.session.on('will-download', onWillDownloadBoundTo(accountUuid));
  attachCaptureEarly(win.webContents, accountUuid); // CDP before first navigation completes
  return win;
}
// Sign-out/destruction: closeAllConnections + clearStorageData({storages:[...]}) scoped
// to that partition only; other partitions untouched. Destructive scope keyed by accountUuid.

Two signed-in accounts = two partitions = two windows (or two WebContentsViews in one window chrome — same isolation, less chrome). Service-worker, cache, and capture contexts are keyed by partitionId everywhere downstream.

  • Modes: battle, direct, side-by-side (+ code/agent text lanes where observable; binaries/artifacts per §10).

6.3 How the stack observes (primary vs fallback)

Primary — browser-process CDP (main)

  • Target.setAutoAttach(autoAttach:true, flatten:true, filter:[page,iframe,worker,service_worker,shared_worker] at window creation; Network.enable(maxTotalBufferSize, maxResourceBufferSize) + Fetch.enable(patterns:[{urlPattern:'*://arena.ai/*'}]) + Page.enable/Runtime.enable per target.
  • Stream reassembly: Network.dataReceived/eventSourceMessageReceived/webSocketFrame* /loadingFinished/loadingFailed → per-requestId byte log → IO.read / getResponseBody on finish; chunked/SSE framing handled by adapter, not by DOM timing.
  • Reconnects/repeated events: dedupe by (partitionId, conversationKey, requestId, seq/eventId); late reveals update identity view without rewriting bytes (§8).
  • Attribution: every event stamped {accountId, partitionId, targetId, frameId, adapterVersion, observedAt} at ingest — before any join.

Secondary — page-world reconciler (preload, least privilege)

  • DOM/reveal/vote join, turn/branch boundaries, regeneration buttons, stop affordance, title/timestamp text. Communicates via append-only, validated IPC (no eval, no Node).
  • Fallback loss if CDP unavailable: no worker/SW bodies, no early-navigation bytes, stream framing from DOM timing only (partial-prone), binary/tool traces degraded to URL references. Fallback mode is explicitly flagged per turn (capturePath: cdp|dom-fallback|import).

7 · Existing-history synchronization (independent from live capture)

Methods compared: navigation observation, rendered-history recording, page-response-data inspection, replaying discovered owner-history reads, UI traversal automation, official/privacy export import, future documented API. Hypothesis to test: whether a stable paginated owner-history read exists (third-party leads suggest cursor-paginated list + per-id detail; unverified).

Recommendation Primary: replay verified owner-history reads

Use only catalogued verified-read list/detail ops, issued via ses.fetch() bound to the correct partition (cookies stay in Chromium; no token export). Robust over brittle DOM traversal; no export assumed.

Practical fallback: guided UI traversal + rendered capture

Automated scroll/search/pagination in the account’s window with rendered-state recording. Slower, rate-sensitive, DOM-fragile — but works even if no stable list endpoint verifies. Official-export import stays an optional reconciler (never assumed complete).

Sync semantics

  • Scope: Sync now for one account or selected accounts; opt-in auto-sync per account (off by default; interval + quiet-hours configurable).
  • Visibility: per-account progress (pages, cursors, bytes, ETA), cancel, resumable checkpoints (cursor + detail-ID frontier persisted per account), bounded retries (exponential backoff + jitter, max attempts, honor Retry-After).
  • Correctness: per-account pagination/checkpoint isolation; overlapping/repeated pages deduped by (accountId, sourceId, updatedAt, contentHash) — identical text alone never dedupes; pagination instability handled by cursor-replay + detail re-fetch; re-runs idempotent.
  • Concurrency: accounts sync concurrently by default (independent schedulers, per-partition rate limiters); if Arena throttles globally, scheduler serializes with documented queue state — correctness never reduced for speed.
  • Live-capture overlap: live turns hold a write lease on their conversation; sync detail for the same conversation merges field-wise (newer observation wins per field, both provenances kept) — no clobber of an in-flight stream.
  • Degradation: rate limit / auth expiry / drift / redirect / challenge / suspected mutation degrades only the affected account (paused + reason + resume hint); others continue.
  • “Synchronized” per account = list frontier exhausted (no hasMore) and detail frontier exhausted and gap ledger empty — with remaining gaps (e.g., archived-only, deleted-remote, detail-404) explicitly listed for agent inspection. Opening one known conversation proves nothing about coverage.

If no reliable listing/pagination/complete-history representation verifies: the design still ships — fallback traversal + live capture + per-conversation detail fetch cover forward history; the gap ledger + catalog state honestly report “list-incomplete” and block any “full-history” claim in exports/analysis cohorts.

8 · Data, identity, provenance, protection

8.1 Source-of-truth: justified hybrid (not full event sourcing)

  • Normalized records (conversations, branches, turns, participants, identity observations, artifacts, sync progress, analysis runs) are the queryable truth.
  • Observations retained as bounded sanitized evidence (not raw network console): shape hashes, redacted samples, parser version, completeness — TTL’d (default 90d, configurable) and sufficient for drift diagnosis + reparse after adapter changes.
  • Encrypted large artifacts in a vault directory (per-account subdirs); DB holds references + hashes, never secrets.
-- core sketch (illustrative DDL; additive migrations only)
CREATE TABLE accounts(
  account_id TEXT PRIMARY KEY, partition_id TEXT NOT NULL UNIQUE,
  display_email TEXT, display_name TEXT, created_at TEXT, last_seen TEXT);
CREATE TABLE conversations(
  id INTEGER PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(account_id),
  source_id TEXT NOT NULL, mode TEXT, title TEXT, created_at TEXT, updated_at TEXT,
  archived INT DEFAULT 0, deleted_remote INT DEFAULT 0,
  UNIQUE(account_id, source_id));           -- collisions across accounts stay separate rows
CREATE TABLE branches(id INTEGER PRIMARY KEY, conversation_id INTEGER NOT NULL,
  label TEXT, position INT, created_at TEXT);
CREATE TABLE turns(id INTEGER PRIMARY KEY, branch_id INTEGER NOT NULL,
  seq INT, role TEXT, markdown TEXT, state TEXT,      -- complete|stopped|failed|partial-observer-missed
  capture_path TEXT, adapter_version TEXT, observed_at TEXT, content_hash TEXT);
CREATE TABLE identity_obs(id INTEGER PRIMARY KEY, conversation_id INTEGER NOT NULL,
  scope TEXT, kind TEXT, value TEXT, source TEXT,     -- ui|network|import|reveal-event|annotation
  turn_range TEXT, observed_at TEXT, adapter_version TEXT);
CREATE TABLE observations(evidence_id TEXT PRIMARY KEY, account_id TEXT, op_id TEXT,
  shape_hash TEXT, redacted_sample TEXT, retained_until TEXT);
CREATE TABLE sync_state(account_id TEXT PRIMARY KEY, list_cursor TEXT,
  detail_frontier TEXT, updated_at TEXT, status TEXT, last_error TEXT);
CREATE TABLE artifacts(id INTEGER PRIMARY KEY, turn_id INTEGER, kind TEXT,
  vault_path TEXT, sha256 TEXT, bytes INT, origin_url_redacted TEXT, capture_state TEXT);
CREATE VIRTUAL TABLE transcript_fts USING fts5(markdown, title, tokenize='trigram');
  • Reconciliation keys: (account_id, source_id) for conversations; (branch, seq, content_hash) for turns. Cross-account source-ID collision → two rows + ownership_conflict flag, never merged.
  • Provenance per normalized field/analysis result: account/session, what was observed, when, mechanism + adapter/parser version, uncertainty/completeness. Recomputable after adapter change via retained sanitized evidence until TTL.
  • Transactions/crash/migration/backup: WAL + per-sync-commit transactions; crash recovery via checkpointed cursors + lease expiry; additive migrations with rollback snapshot; backup = encrypted DB copy + vault snapshot manifest; restore verifies hashes before index rebuild; deletion cascades to FTS/derived rows synchronously, analysis runs referencing deleted data are tombstoned (not silently recomputed).

8.2 Model identity (preserve, don’t equate)

  • Store separately: selected labels, blind labels (A/B), displayed provider/model names, post-vote reveals, timestamps/turn ranges, source (ui|network|import|reveal-event|annotation).
  • Never silently equate position ↔ blind label ↔ provider ↔ marketing name ↔ route ↔ exact build. Conflicts/unknowns preserved; usable identity view layers reveal onto lanes without erasing earlier evidence or over-attributing scope (e.g., “revealed for turns 12–18 in conversation X only”).

8.3 Archive capabilities & security

  • Offline-first: local text search + filters (account, date, mode, observed/revealed model, state, provenance); branch-aware transcripts; versioned machine-readable export (JSON + provenance manifest) + human-readable Markdown. Cross-account search allowed; account source always visible; exports support one / selected / all accounts without collapsing boundaries.
  • Encryption: random 256-bit archive key in Keychain (via safeStorage); primary DB SQLCipher (AES-256-CBC per-page, per-page IV, HMAC, PBKDF2-HMAC-SHA512 salt — per SQLCipher design doc Verified fact); FTS inside the encrypted DB; vault files encrypted at rest (per-file data keys wrapped by archive key); temp files on encrypted APFS + immediate wipe.
  • Plaintext exposure map: browser partition storage (cookies/cache/SW — OS file-permission protected, excluded from exports/backups-diagnostics, wiped per-account on deletion); temp/WAL/journal (SQLCipher-encrypted pages; temp-store constrained to memory); logs/crash reports (sanitized, no bodies/secrets); Spotlight (vault + DB dirs marked excluded + .nomedia-style no-index); swap (memory locking where available + key zeroing); Time Machine (encrypted backups inherit FileVault; documented as residual risk with exclusion guidance); exports/fixtures (never include credentials by construction + pre-export secret scan gate).
  • URL secrets: source URLs with tokens/signatures stored only as {host, path-template, query-shape-hash}; display form strips query/fragment.
  • Deletion: one conversation (rows + FTS + vault refs + derived excerpts tombstoned); one account’s local data (partition wipe + rows + vault subdir + sync state; dedup markers for that account dropped so a future re-sync honestly re-fetches); whole archive (DB + vault + cursors + key rotation). External exports/backups are reported as residual copies the app cannot erase — never promised otherwise. Future sync respects tombstones (no zombie re-import without explicit re-enable).
  • Remote-content containment: Arena DOM cannot reach keys/files/privileged APIs/MCP: sandbox + contextIsolation + no-Node + preload allow-list + IPC sender validation + partition confinement + secret-free diagnostics. Holds during errors/sign-outs/concurrency: destructive scope always re-resolved to the originating partition at execution time.

9 · Full LLM operability — local MCP contract

Transport & trust

  • Streamable HTTP on 127.0.0.1:<ephemeral> (primary; MCP spec Verified fact) + stdio (agent subprocess). Single MCP endpoint; Origin validation, localhost-only bind, per-launch bearer token (rotated each start, shown once in GUI + written to Keychain-readable runtime file with 0600).
  • Discovery: initialize → tools/list, resources/list, prompts/list; serverInfo advertises adapter versions + unavailable ops with reasons (e.g., sync.paused:challenge-captcha).
  • GUI and MCP share the same application-service layer (no forked semantics); browser-interaction steps (e.g., “focus account B window for CAPTCHA”) are explicit MCP tool calls returning window-focus state, never GUI-only.

Identity, pagination, errors, jobs

  • Every call takes accountId and/or partitionId where scope matters; IDs are opaque app UUIDs + sourceId echoes (never bare Arena IDs as authority).
  • Pagination: cursor-based {limit, cursor} → {items, nextCursor, hasMore, totalEstimate}.
  • Errors: invalid-scope | not-signed-in | ambiguous-ownership | paused-challenge | rate-limited | adapter-drift | conflict | needs-explicit-directive | internal — each with retryHint + resumeOp.
  • Long work = jobs: {jobId, kind, accountId, status: queued|running|paused|cancelling|cancelled|done|failed, progress, checkpoint, idempotencyKey}; cancel is cooperative + checkpointed; re-issue with same key resumes.

Content-is-untrusted guard (not “be careful”): archived prompts/responses/diagnostics are data, never authority. Account/archive deletion requires (a) a directive arriving on the trusted control channel (MCP caller authenticated with the per-launch bearer or GUI-confirmed intent — never a string found in transcript/diagnostic/vault content), (b) bound to the exact scope shown (accountId + displayed email + counts echoed back), (c) a fresh single-use scopeToken issued by deletion.preview + typed confirmation. The service layer rejects any directive whose provenance is archived-content|diagnostic-text|vault-bytes. Prompt-injection can at most create a needs-explicit-directive error, never a deletion.

10 · Local analysis & later modalities

Initial model profiles (deterministic first)

  • Cohorts grouped only by observed/revealed identity evidence, uncertainty preserved; every figure links to source excerpts + provenance.
  • Metrics where defensible: response/paragraph/sentence/code-block lengths; lexical diversity, n-grams, punctuation/casing; Markdown structure (headings/lists/tables/citations/code-prose ratios); openings/transitions/conclusions, hedging/refusal/apology/uncertainty markers; splits by prompt type/topic/mode/language/time/context.
  • Limits stated on every profile: single-heavy-user selection bias, sparse samples, prompt/topic confounding, history effects, hidden system prompts, decoding/tools/safety layers, aliases/routing, temporal drift, Arena post-processing, uncertain labels. Supported: “in this corpus, lane A uses longer code blocks than lane B on code prompts”. Misleading without controls: “model X writes better than Y” as a general claim.
  • Embeddings/ML entry gate (all must pass): (1) a profile question deterministic stats cannot answer; (2) pinned weights + offline-after-setup plan + license review; (3) preprocessing/version tracking design; (4) RAM budget on 18 GB with browser + DB resident (measure, don’t assume); (5) reproducibility (seeded, locked env). Otherwise stay deterministic.

Similarity / fingerprinting experiments (later, gated)

Similarity to corpus = confidence-qualified hypothesis, not identity proof; inferred identity stored separately from observed identity. Predeclared: leakage-resistant splits (held-out conversations, near-duplicate/branch-aware grouping), prompt/topic controls, negative + unknown-class handling, calibration, reproducible seeds, minimum-evidence analysis (empirical learning curves, no invented thresholds). Continue / revise / abandon on predeclared utility criteria; null results are publishable-in-archive, not failures to hide.
