# App-wide UI rework (2026-10-18)

Request (after the sidebar rail): "i am not a fan at all of the ui at the top, rework that
completely please. in fact, please rework the ui and layout of the whole app please, don't push
this new ui to github until after i approve of it".

The model for the layout is the site itself: its sidebar holds the entries, the chat history and
the account. The previous toolbar used the system's glass capsules ("Reasoning & tools", the
format picker, the export and evidence buttons). The user objected to those.

**Status:** built and checked in the Debug build; committed locally. **Not pushed:** it waits for
the user's approval.

## Acceptance criteria

1. **No system title bar or toolbar.** The window keeps only its buttons. Each pane draws a 32 pt
   header bar in the window's top band.
   - The bar is centered on the window buttons, which sit 16 pt from the top on macOS 26
     (measured with a standalone window).
   - The band stays draggable, and buttons in it take clicks (both checked with real pointer
     events on a standalone window).
2. **Sidebar like the site's.**
   - Entries at the top: the site, Search (⌘F) and Sync History.
   - Then the archived conversations, newest first, grouped by date: Today, Yesterday, Previous 7
     Days, Previous 30 Days, then by month.
     - The date is the instant the decoder parsed, which is the key the list is sorted by
       (`ConversationSummary.updatedOrder`). The UI does not parse timestamps again.
     - A conversation without that instant goes under "Undated", last, never guessed.
     - A date after now (clock skew) gets its month, never "Today".
   - Each row shows a modality symbol and the title. The details are in its tooltip: mode,
     modality, local date, "list only", snapshots, "no longer on Arena".
   - At the bottom, an account switcher like the site's account row.
3. **The account switcher** chooses the scope: all accounts or one. The history, search, the site
   entry and Sync History follow it. It also opens the Accounts and Maintenance pages.
4. **Rail.** The collapsed sidebar has the same entries as icons: toggle, site, search, sync, a
   warning when there is a message, and the account switcher. Control-Command-S and the automatic
   collapse on opening the site are unchanged.
5. **Archive pane.**
   - Header: the title, mode, modality, account (when there are several) and local date. Then a
     snapshot menu (when there are several), an export menu and the evidence toggle (⌥⌘0).
   - The transcript is a centered column:
     - model claims, each with its source;
     - your prompt as a bubble on the trailing side;
     - responses as outlined cards with a lane badge and the model;
     - reasoning, tool calls, tool results and sources collapsed under a chevron;
     - votes as a small capsule.
   - The evidence panel is fixed at the trailing edge, with its own header.
   - After an export, a notice floats at the bottom with Reveal in Finder.
6. **Accounts and Maintenance are pages** in the window, with the same header bar. They are no
   longer sheets, so there is no system footer strip and nothing overflows the window. The sign-in
   form is still a sheet, now in the app's typeface with its own fields.
7. **Site pane.** Header bar:
   - Back, Forward, Reload/Stop and Home;
   - the profile title (`<site> · web profile of <account>`), and the host when it differs from
     the site's;
   - Sync History or Stop Sync;
   - a More menu (Open Page in Browser, Close Session, Clear Web Data…).

   The closed placeholder uses the app's typeface.
8. **Unchanged:**
   - The site loads only from the user's click (`openSite` → `ArenaWebProfiles.open`), and ADR
     0006 holds.
   - Search, export (including the confirmed exact-raw export), evidence and keyboard navigation
     work as before.
   - The Debug preview flags still work.

### One behavior change: Sync History for all accounts

With "All accounts" chosen, Sync History starts each signed-in account's own sync job. Before, the
user started each account separately.
- Plan v3 §2 still holds: it is user-initiated, and each job keeps one request in flight for its
  account.
- With one account chosen, it syncs that account only.
- While any sync runs, in scope or not, the entry is Stop Sync and stops every running job.
  Narrowing the scope never hides a running job.
- Each account's failure is kept until that account syncs successfully or the user dismisses it.

## Limits

- **The 32 pt header bar is fitted to macOS 26.** The window buttons there were measured 16 pt
  from the top. On older systems, which the app still supports (macOS 14), they may sit a few
  points higher than the bar's center.
- **The open site's header with a real page is the user's live check.** Its controls were seen
  only with the preview page model.
- **Search snippets still show the index's `[` `]` match markers.** They cannot be told apart from
  brackets in the text, so they are not restyled.
- **Light mode was checked only once,** with the Debug build forced to the light appearance. It is
  coherent, but its palette is still a guess (the site's light theme was never sampled).
- **The fixed sidebar width (260 pt) stays.** So does the rail's use of initials, from the rail
  milestone.
