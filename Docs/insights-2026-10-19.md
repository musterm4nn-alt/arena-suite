# Insights (2026-10-19)

A read-only page that summarizes the user's own archive: how much is archived, when, in which
modes, how the user voted, and each model's record in those votes.

The user asked on 2026-10-19 to "design, develop, implement new features and improvements". This is
the first such feature.

It reads the index only. It sends nothing to Arena, writes nothing and changes no evidence. It never
suggests, prepares or automates a vote (plan v3 §1).

## Evidence it relies on

- **N-016:** the vote values observed are `model_a`, `model_b`, `tie` and `both_bad`.
  - Their meaning ("A is better", "B is better", "tie", "both are bad") is an **assumption** from
    the names. It is recorded in the ledger.
  - The vocabulary lives in `ArenaAdapter` (`ArenaArchiveDecoder.voteVocabulary`). The app hands
    it to the service, so only the adapter knows Arena's values.
  - Any other value is shown as unrecognized and never interpreted.
- **N-015:** every vote carries the two models it compared (`pairwiseFeedbacks[].modelAId` and
  `modelBId`), and all 148 of these claims agree with the messages' own `modelId`.

## Scope (named on the page)

- **One snapshot per conversation:** the latest. Earlier snapshots are history; the latest
  snapshot of each conversation is what the archive currently holds for it.
- **Accounts:** the sidebar's account choice (all accounts, or one).
- **Activity:** months by each conversation's last update as Arena reports it (`updatedAt`), in the
  Mac's calendar and time zone. Conversations without a parsable update time are counted as undated.
- **Votes:** only votes between two responses (`pairwiseFeedbacks`). Feedback on a single response
  (`pointwiseFeedbacks`) is not decoded; any keys inside it are reported as unknown fields and the
  record stays in the journal. The real archive has none (below).
- **Model records:** only votes whose value is in the vocabulary, and whose sides each have exactly
  one claimed model.
  - A side's model is the vote's own claim for that side (`pairwise_feedback`), plus the voted
    message's `modelId` (`message_model_id`).
  - If these disagree, the vote is excluded as "conflicting claims", never merged.
  - Votes with no claim, or with the same model on both sides, are excluded and counted by reason.
- **Model names:** the name Arena revealed for that model ID (`detail_revealed`), from any snapshot,
  so a name is not lost when a later snapshot omits the reveal. Where several names were revealed,
  the one from the latest record is used. Without one, the model ID is shown.
  - Model IDs are Arena's own, so under all accounts a name revealed in one account labels the same
    ID in another.
- **Not identity:** these are claims recorded in the archive, never verified identity. The page
  says "claimed".
- **Not a leaderboard:** a model's record is the user's own votes, not Arena's ranking.

## Acceptance criteria

1. **One read.** `ArchiveIndex.insightsSource(accounts:)` reads conversations, latest-snapshot
   messages (without bodies), votes and claims in one read transaction.
2. **Pure aggregation.** `ArchiveInsights.build(source:vocabulary:calendar:)` is deterministic.
   Tests cover:
   - counts by mode, kind and account;
   - month buckets in a fixed time zone, including empty months and undated conversations;
   - vote outcomes, including unrecognized and missing values;
   - attribution with each exclusion reason (no claim, conflicting claims, same model);
   - the latest revealed name winning;
   - the account filter;
   - only latest snapshots counted.
3. **Real decoding.** An end-to-end test through `ArenaArchiveDecoder` and journal records gives the
   expected records, and the adapter's vocabulary maps exactly the four N-016 values.
4. **The page.** An "Insights" entry in the sidebar and rail opens a page in the app's style
   (Departure Mono, Theme colors, no new frameworks). It shows:
   - totals;
   - activity by month;
   - modes;
   - "your votes" by outcome;
   - each model's record (votes, preferred, not preferred, ties, both bad);
   - the exclusions, and the scope line.

   It follows the account choice and reloads after a sync, rebuild or restore. An empty archive
   shows the first step instead of empty charts.
5. **Checks.** `Scripts/test-offline.sh` passes, the boundary check passes and the Debug app builds
   without warnings. A second model reviews the change.

## Results (2026-10-19)

- **Tests:** 10 index and aggregation tests (`InsightsTests`) and 2 adapter tests
  (`InsightsAdapterTests`), all passing. Both suites check that every attributed vote adds one to
  each of its two models and that each record's outcomes add up to its votes. `Scripts/test-offline.sh` exits 0, the boundary check
  passes, and the Debug app builds without warnings.
- **Real archive** (counts only, `realArchiveInsightsAttributeEveryInterpretedVote`; the index is
  rebuilt in a temporary folder from the journals and removed):
  - 3 accounts, 60 conversations (54 with a transcript), 312 prompts and 325 responses in the
    latest snapshots, 4 modes, 5 months, none undated.
  - 74 votes: 35 `model_a`, 36 `model_b`, 1 `tie`, 2 `both_bad`. No other value, none without a
    value.
  - All 74 votes are attributed, with no exclusion, across 55 claimed models. This matches N-015:
    every vote's claims agree with its messages.
  - No unknown field under `pointwiseFeedbacks`: no single-response feedback with content is
    recorded, so the pairwise votes are all the votes the decoder could see.
- **The page,** checked in the Debug build against a synthetic archive (made-up models and titles)
  and an empty one:
  - The totals, the activity chart, modes and kinds, the votes and the models table render.
  - Scrolled content stays below the header bar.
  - The empty state offers the first step, and the rail entry shows as selected.
