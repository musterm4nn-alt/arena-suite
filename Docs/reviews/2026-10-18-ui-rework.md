## Findings and fixes

| # | Finding | Fix |
|---|---|---|
| 1 (Medium) | Concurrent syncs shared one error slot: one account's success cleared another's failure (for example a 403 stop). | Failures are kept per account in `AccountsModel.syncErrors`. A success clears only its own account's entry. They show in the sidebar status, the rail's warning and the Accounts page; Dismiss clears them. Manifests and the status file were and are unaffected. |
| 2 (Medium) | The UI parsed `updatedAt` with its own, looser rules than the decoder that sets the sort key. | The UI parser is gone. `ConversationSummary` now carries `updatedOrder`, the decoder's exact instant that the list is already sorted by. Grouping uses only that; without it a conversation is "Undated" and last, which is its sort position. New test `listingCarriesTheParsedUpdateInstantInListOrder`. |
| 3 (Medium) | Narrowing the scope hid a running sync and its Stop. | The sync entry, its progress and Stop cover every running job. Only starting is scoped. |
| 4 (Medium/Low) | N concurrent syncs triggered N full index updates, and "Updating index…" flickered. | `onSyncFinished` updates the index only when no other sync is still running. Two jobs finishing in the same moment may still update twice, which is harmless because projection is idempotent. |
| 5 (Low) | A future-dated conversation was grouped under "Today". | A negative day count falls through to the month heading. |
| 6 (Low) | A date formatter was built per old conversation. | One shared formatter (already changed while the review ran). |
| 7 (Low) | A search hit that opens another conversation could miss its scroll, because the request arrives in the same update as the transcript. | `.task(id: scrollRequest)` also runs when the transcript first appears. |
| 8 (Low) | The prompt's evidence button is invisible until hover but still took clicks. | It takes no clicks while invisible. It deliberately stays in the accessibility tree, because VoiceOver cannot hover. |
| 9 (Low) | The rail's "open session" dot had no accessibility value. | `accessibilityValue("open")` on the rail's site icon, and a tooltip note. |
| 10 (Low) | ⌘F with the full sidebar might not focus a field inserted in the same update. | Focus is also set on `onChange(of: searching)`. ⌘F, typing and Esc were checked with keystrokes on the Debug build. |
| 11 (Low) | The doc said "committed locally" before the commit existed. | True once this change is committed, which happens before any approval or push. |
| 12 (Low) | Unstated removal of the remembered export format; unused `arenaBackground`; in the Debug site-header preview, "Clear Web Data…" does nothing. | Removal recorded in the milestone doc; `arenaBackground` deleted. The preview no-op is accepted: Debug-only, and it opens nothing. |

## Test gaps raised

  automated tests (open since the first review). The grouping now depends on a value the index
  computes, and that value is tested.

  projection count). `AccountsModel` lives in the app target, so this waits for an app test target.
