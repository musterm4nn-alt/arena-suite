## Findings and what was done

| # | Finding | Outcome |
|---|---|---|
| 1 (Medium) | The vote totals read as the user's whole vote record, but only pairwise votes are decoded; `pointwiseFeedbacks` elements are not projected. | **Fixed.** The tile, the section and the footnote say "votes between two responses" and that feedback on a single response is not decoded and stays in the journal. The real-archive test now also counts unknown paths under `pointwiseFeedbacks`: there are none (the live index agrees: 0 of its 2 unknown paths). |
| 2 (Medium) | The two attribution invariants (votes add up per record; Σ votes = 2 × attributed) were asserted only in the opt-in real-archive test. | **Fixed.** Both are asserted in the always-run tests: the adapter test through `ArenaArchiveDecoder`, and three index tests through a shared helper. |
| 3 (Low) | "No claimed model" also covers a vote naming a message missing from the snapshot. | **Fixed by wording.** The page says "with no claimed model found for a side", and the reason's doc names both causes. New test `aVoteNamingAMessageOutsideTheSnapshotHasNoModelForThatSide`. |
| 4 (Low) | `insightsSource` joined messages and claims to a conversation by sequence alone. | **Fixed.** Both joins also match the conversation ID. New test `rowsOfAnotherConversationInTheSameRecordAreNotCounted`: one record holding c1's snapshot and a listing for c2 with a claim on c1's vote. It fails without the fix (the vote becomes a conflict). Votes have no conversation column; one snapshot per (account, sequence) is the `snapshots` table's primary key. |
| 5 (Low) | Revealed names came only from the latest snapshot, so a later snapshot without the reveal lost the name. | **Fixed.** Names come from every named claim of the requested accounts (`InsightsSource.namedClaims`), latest record first. New test `aNameRevealedInAnEarlierSnapshotIsKept` fails without the fix. |
| 6 (Low) | Under all accounts, a name revealed in one account labels the same model ID in another; the account filter is applied in Swift, not SQL. | **Documented, not changed.** Model IDs are Arena's own, so this is the same model. The doc and a code comment say so. Filtering in Swift reads every account's rows but returns only the requested ones; it is correct, and the archive is small (60 conversations). |
| 7 (Low) | "Last update" is presented as a fact, without naming whose timestamp it is. | **Fixed by wording.** The page says "their last update, as Arena reports it", and the footnote names this Mac's calendar and time zone. The existing Tokyo/UTC test covers the month boundary. |
| 8 (Low) | `InsightsMessage.lane` and `.conversationID` were carried but never read. | **Fixed.** Both are removed from the type and the query. |

## Test gaps raised, and what was done

- **Covered now:**

    target; this is only build-checked and was exercised by hand in the Debug build.

    covered by its own tests rather than this milestone's.
