# Review — Site account tabs and the rail's border (2026-10-20)

- **Reviewer:** opencode, `deepseek-v4.1-flash-free#high`, `reviewer` agent, run standalone. The
  author was a different model (Claude Opus 5.5).
- **Why:** the change is in the embedded site's pane (ADR 0006): a new way to open a session.
- **Scope:** `App/ArenaWebPane.swift`, `App/Theme.swift`, `App/MainView.swift` and the fourth
  iteration of `Docs/arena-window-2026-10-18.md`, which states the acceptance criteria. The other
  uncommitted milestone (unfinished conversations and Refresh) was reviewed separately.

## Review

- **Reviewer saw the real diff:** yes, for the three files and the doc section. It also read the
  three files in full, ADR 0006 and the sidebar's site entries.
- **Reviewer ran tests:** none (the change has no tests); its permissions blocked
  `Scripts/check-boundaries.py`, so it read the script. The author ran it (below).
- **Verdict:** "not ready". It found the ADR 0006 session model intact:
  - rendering the tabs opens nothing;
  - a tab's click goes through the same `openSite` as the sidebar, and `ArenaWebProfiles.open`
    returns the account's existing session or creates its one session;
  - nothing is read from a page;
  - switching tabs changes only what is shown, never which account a page or a sync belongs to.

  It found the border and rail logic sound, and asked for findings 1 and 2 to be fixed.

| # | Finding | Outcome |
|---|---|---|
| 1 (Medium) | The tab row had no width limit: several accounts, or long names, could squeeze out Sync History and the More menu (Close Session, Clear Web Data). | **Fixed.** The tabs sit in a `ViewThatFits` that falls back to a horizontal `ScrollView`; Sync History and Stop Sync have a fixed size (More already had one). Checked with six accounts: the open header's tabs scroll and the controls stay whole. |
| 2 (Medium) | The accessibility label didn't say whether a click shows or opens a profile, though the doc said so, and the background dot was visual only. | **Fixed.** The accessibility value says "Shown", "Shown, closed", "Open in the background" or "Closed"; the hint says "Shows its page" or "Opens its session"; the dot is hidden from accessibility; the selected tab's help starts "Shown:". The doc now says which is which. Not checked with VoiceOver. |
| 3 (Low) | In light mode, unselected tab text at 60 % opacity was about 4.4:1, just under WCAG AA. | **Fixed:** 70 %. |
| 4 (Low) | The clear strip above the border was hit-testable inside the window buttons' band. | **Fixed:** the border column has `allowsHitTesting(false)`. |
| — | Two comments still said a session starts from "the user's Open click". | **Fixed:** they name Open, a site entry and a tab. |

Test gaps it named: there is no UI test target, so the tabs' count, selection, dot, accessibility,
layout at minimum width, the rail rule in `openSite` and the border's hit testing are untested. They
were checked in the app where possible (`Docs/arena-window-2026-10-18.md`, fourth iteration).
