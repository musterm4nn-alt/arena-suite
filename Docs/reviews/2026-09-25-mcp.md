## Findings and fixes

| # | Finding | Fix |
|---|---|---|
| H1 | `list_accounts` loaded the registry through `PrivateFile.read`, which `chmod`s a loose file, so a read-only session could change the registry's mode. | New `PrivateFile.readWithoutTightening` / `AccountRegistryStore.loadWithoutTightening` refuse permissions wider than `0600`/`0700` and symlinks, and change nothing. `list_accounts` reports the refusal. Test `looseRegistryIsRefusedNotTightened`. |
| M1 | The boundary deny-list missed `apply`, `reset`, `replay`, `checkAgainstJournal`, `export(…to:)`, `save`, `PrivateFile`, `FileManager` mutations, `Data.write(to:)`, and POSIX `open`/`chmod`/`unlink`/`rename`. | The deny-list was widened into a compiled constant. It self-tests on every run against 15 forbidden probes and 3 allowed forms. The factory was renamed `ArchiveTools.readOnly(archiveRoot:)` so `open(` stays forbidden. |
| M2 | `serve()` buffered without a limit and dropped a final line with no newline. | New `LineFramer`: 16 MiB line cap (reported once as `-32600`, then discarded to the next newline), trailing CR stripped, blank lines skipped, final line delivered at EOF. Test `framerHandlesSplitsCRLFBlanksEOFAndOversizedLines`. |
| M3 | Unexpected errors were interpolated into tool results, whose text is not ours to vouch for. | The client gets only the error's type name. Test `argumentsAreBoundedAndErrorsCarryNoContent` truncates the journal and checks that the error names no text, telemetry key or path. |
| M4 | `JSONValue` bool/int/double handling was assumed, not tested. | Table test `jsonValueKeepsBoolsIntsAndDoublesApart`. `1` stays an int, integers past `Int64` are not trusted as sequences, and large sequences travel as strings. |
| L1 | `conversation_id` was unbounded. | Capped at 256 bytes and not echoed when too long. `offset: Int.max` returns an empty page (tested). The O(N) paging is acceptable at archive scale. |
| L2 | The `-shm` exemption did not cover the file being created. | Test `sessionWithoutSharedMemoryFileOnlyCreatesIt`: with `-shm` removed, a session creates only `-shm`, and every other file stays byte- and mtime-identical. |
| L3 | The read-only decoder version fell back to `"unknown"`. | Now `"unprojected"`, which names the state. |
| L4 | Check-then-open race, and symlinked parent directories are not detected. | Documented as a local-threat limit in the phase doc. The same trust boundary applies to the app's own index open. |
