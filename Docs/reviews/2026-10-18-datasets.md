## Findings and fixes

| # | Finding | Fix |
|---|---|---|
| M1 | "Digest checked" overstated the check. The index stores no independent record digest, so the check is the journal reader's own framing and SHA-256 record digest, plus sequence and account. | The wording is now exact in criterion 2, in the `sourceRecord` doc comment, in the manifest `problem` strings, and in a new manifest `source.record_check` statement. `record_digest` is described as the verified journal digest, kept so a later reader can check the journal against it. |
| L2 | An unreadable envelope, or one without a valid `account_id`, was reported as `source_record_account_mismatch`. | New `DatasetService.classify(envelope:digest:account:)`. An unreadable envelope or a missing or invalid account gives `source_record_unavailable`; only a readable envelope naming another account is a mismatch. Test `sourceRecordEnvelopeIsClassifiedByWhatWasObserved`. |
| L3 | `groups_across_splits` cannot fire through the pipeline: it is a consistency check, not an independent recount. | Kept as a consistency check of split assignment against grouping, and described that way in the code and criterion 8. The independent recount is the other overlap keys. |
| L4 | The near-duplicate recount reused the grouping's LSH pairs, so a pair LSH missed escaped both grouping and the audit. | `DatasetService.nearAcross` recounts by exact Jaccard over every pair of distinct included texts in different splits, with a size bound first. Above 2000 distinct texts it falls back to the LSH pairs, writes a note, and the audit's `grouping.near_duplicate_recount` names the method. The unit test now finds a near-duplicate pair with no LSH pair given, and rejects a below-threshold pair that LSH proposed. The real archive is still clean. |
| L5 | `manifest.labels` took display names, organizations and providers from every account, even in an account-scoped build. | The label table is limited to the recipe's accounts; the leakage vocabulary stays global by design. Test `manifestLabelTableNamesOnlyTheSelectedAccounts` (account B has its own display name for `m-alpha`). |
| L6 | A process killed mid-build leaves a staging folder that is cleaned up only by a later build, and only once it is an hour old. | Documented exactly in criterion 9. The age guard stays, so a concurrent build's staging folder is never removed. The leftover is owner-only and hidden. |
| L7 | The handoff cited this review file before it existed, and the status said "review pending". | This file now exists, and the status and handoff were updated together. |
| L8 | `--preview-dataset` ran Validate. | Renamed to `--validate-dataset`. |
