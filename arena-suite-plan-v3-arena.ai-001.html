SECTION 01 // PRIORITY 01 RECOMMENDATION VERIFIED FACT BASELINE

Executive Decision: Dedicated Electron Browser Shell with Out-of-Band Browser-Process CDP & Hardware-Isolated Session Partitions

To permanently escape the architectural ceiling of the existing Manifest V3 extension baseline (musterm4nn-alt/arena-exporter v2.1.3), the recommended architecture is a private, single-binary Apple Silicon (arm64) Electron application that embeds concurrent arena.ai sessions inside isolated WebContentsView instances backed by persistent, non-overlapping Chromium storage partitions (persist:arena_acct_<ulid>) and observes all traffic out-of-band from the privileged Browser Process via Chromium DevTools Protocol (webContents.debugger v1.3).

Architecture Comparison: Why Owning the Window Does Not Equal Deeper Capture Privileges

A critical error in desktop browser wrapper design is assuming that embedding a web view automatically grants network capture privileges superior to a browser extension. In reality, Native Swift + WKWebView and Tauri / Wry provide weaker network body observability than even a Chrome extension because Apple's public WebKit API forbids intercepting https:// schemes via WKURLSchemeHandler and exposes no public network response stream tap—forcing 100% reliance on page-world window.fetch monkey-patching (WKUserScript). Only Chromium-based embeddings exposing the browser-process DevTools / Network Service layer (Electron or CEF) provide true out-of-band stream, Worker, and ServiceWorker observation.

DEEP DIVE // ELECTRON VS. CEF DECISIVE SELECTION RATIONALE

Focused Comparison: Electron/Chromium vs. CEF

Both Electron and CEF embed the full Chromium Content module and Network Service, making both technically capable of out-of-band capture. We select Electron over CEF for four concrete architectural reasons:

  1. Capture Equivalence via Response-Stage CDP + Node Streams: While CEF exposes C++ CefResponseFilter::Filter(), Electron's Browser Process attaches CDP Fetch.enable({ patterns: [{ urlPattern: 'https://*.arena.ai/*', requestStage: 'Response' }] }) combined with Fetch.takeResponseBodyAsStream (which reads the raw Mojo data pipe in the Browser Process while teeing bytes back to the renderer) and Network.dataReceived. This achieves identical byte-level visibility in the Browser Process without writing custom C++ ring buffers.
  2. Worker & ServiceWorker Auto-Attachment: Both stacks use the exact same Chromium Target.setAutoAttach({ autoAttach: true, waitForDebuggerOnStart: true, flatten: true }) protocol under the hood to pause and attach to Dedicated Workers, SharedWorkers, and ServiceWorkers before their first instruction executes.
  3. Multi-Account Partition Ergonomics: Electron's session.fromPartition('persist:arena_acct_<ulid>') dynamically provisions isolated disk caches, cookie stores, and ServiceWorker registries in 3 lines of TypeScript and binds them to side-by-side WebContentsView instances inside a single macOS window.
  4. AI Agent Autonomous Operability: AI coding agents can compile, hot-reload, run Playwright/Electron-CDP automated verification harnesses, and debug Node/TypeScript + better-sqlite3-multiple-ciphers in seconds. A C++/Obj-C++ CEF build requires multi-gigabyte binary framework linking and fragile CMake/Xcode bridging that slows agent iteration by an order of magnitude.

Owner-Session Technical Classification & Simultaneous Multi-Account Partition Model

The application operates exclusively on the owner's signed-in Arena accounts. At least two Arena accounts remain signed in and active simultaneously with strict hardware/process partition isolation: cookies, IndexedDB, CacheStorage, ServiceWorkers, capture pipelines, sync cursors, and destructive actions cannot cross partition boundaries.

MECHANISM CLASS 01 AUTHENTICATED READ

1. Authenticated First-Party Read Access

Using the account's own browser session (persist:arena_acct_<ulid>) to read documented or undocumented first-party Arena endpoints—such as conversation history lists, evaluation turn details, public model catalogs, and Cloudflare R2 snapshot blobs.

  • Why it is NOT a bypass: The server authenticates the partition's first-party session cookie and authorizes access to conversations owned by that user ID.
  • Account Binding: Executed exclusively via session.fromPartition(partitionId).fetch(); credentials never leave the Chromium Network Service memory for that partition.
MECHANISM CLASS 02 AUTOMATION COMPATIBILITY

2. Automation Compatibility & Anti-Detection

Ensuring the embedded Chromium session presents as a standard Apple Silicon macOS browser so normal email sign-in, OTP verification, and Cloudflare Turnstile challenges succeed without friction.

  • Concrete Measures: Strip Electron/* token from User-Agent and Sec-CH-UA client hints; disable navigator.webdriver flag via --disable-blink-features=AutomationControlled; never call CDP Runtime.enable on the main world (which Turnstile scripts detect via Console/Runtime stack inspection).
  • Owner-Driven Auth: Popups, magic links, OTP fields, and CAPTCHA widgets render interactively inside the account's dedicated WebContentsView.
MECHANISM CLASS 03 CLIENT-SIDE WORKAROUND

3. Client-Side Restriction Workarounds

Reaching data already transmitted to the owner's machine that the client UI obscures, truncates, or isolates inside cross-origin sandboxes.

  • Actual Control & Mechanism: (a) UI Virtualization / Collapsing: Long battles unmount off-screen DOM nodes; our Browser-Process CDP stream tap captures the full wire transcript before UI pruning. (b) Sandboxed Code Arena Iframes: Cross-origin preview frames block parent-window DOM scripts via SOP/CSP; our Browser Process attaches directly to the OOPIF target (Target.setAutoAttach) and downloads R2 workspace blobs out-of-band.

  • Independent Pause / Cancel / Stop State Machines: Each partition maintains its own capture and sync state (ACTIVE, PAUSED_FLUSH_IN_FLIGHT, CANCELLED_DISCARD_BUFFER, STOPPED_DETACH_CDP). SYNCHRONOUS SECURITY GATE PRE-PERSISTENCE SANITIZER

Zero-Credential Sanitization Pipeline

No raw network capture, parser failure dump, or DOM snapshot may touch SQLCipher, disk journals, or MCP diagnostic responses before passing through SanitizerPipeline.scrub(event) in the Electron Main process:

  • Header Allowlist (Strict Drop-By-Default): All request and response headers are dropped except the verified diagnostic allowlist: content-type, x-session-settled, x-stream-version, x-arena-chat-id, retry-after, and x-ratelimit-*. Cookie, Set-Cookie, Authorization, X-CSRF-Token, and cf-ray/clearance headers are unconditionally destroyed in RAM.
  • Recursive JSON & Nested-String Scrubbing: Parses JSON and JSON-encoded strings recursively, redacting keys matching /(token|secret|password|cookie|authorization|api[-_]?key|captcha|turnstile|cf_clearance|otp|code|signature|credential)/i and regex-matching Bearer/Basic headers, JWTs (eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+), and private keys.
  • Safe Resource Reference Canonicalization: When Code Arena or image turns reference signed URLs (e.g., Cloudflare R2 presigned URLs containing ?X-Amz-Credential=...&X-Amz-Signature=...), the sanitizer extracts the binary payload via the partition's downloader, hashes the content (sha256), and replaces the URL in all stored records with a deterministic, secret-free URN: urn:arena-archive:artifact:sha256:<hex>?host=r2.cloudflarestorage.com&path=/snapshots/eval_123/workspace.zip.
  • Fail-Closed Parser Error Behavior: If a JSON/Flight stream chunk throws a syntax error during drift, the raw chunk is still passed through regex & entropy credential scrubbing before being written to the raw_evidence_blobs quarantine table. If the sanitizer itself throws an exception, the payload is discarded in RAM and only an error code + structural byte length is logged.

MULTI-ACCOUNT SYNC SCHEDULING & RATE LIMITS CONSERVATIVE TOKEN BUCKET

Concurrent Account Sync & Cross-Account Collision Rules

  • Serialized Network Token Bucket Across Active Partitions: While Partition A and Partition B maintain completely independent sync cursors and state machines (`sync_checkpoints` table keyed by `account_partition_id`), both share the same residential egress IP on the M3 Pro. To prevent triggering Cloudflare/Arena IP-level 429 rate limits (Hypothesis EV-11), the Sync Coordinator schedules backfill hydration requests through a global round-robin token bucket capped at 0.4 requests/sec (1 request every 2.5s with ±600ms uniform jitter), interleaving Partition A and Partition B safely while giving immediate priority to interactive live user streams.
  • Live-Capture vs. Backfill Overlap Resolution: If `Sync Now` attempts to hydrate `arena_conversation_id = X` while `X` currently has an `ACTIVE` live stream in that partition, the Sync Engine skips `X` and queues a post-stream verification check. When merging a historical hydration payload into a conversation that already has live-captured turns, live-captured wire chunks (`COMPLETE_VERIFIED` + `raw_evidence_blob_id`) always outrank historical summary payloads (which often omit intermediate reasoning tokens or aborted retry attempts).
  • Cross-Account Source-ID Collision Rule: Every record's primary identity is the composite key (account_partition_id, arena_conversation_id). If the same `arena_conversation_id` (e.g., a shared public battle link opened in both Account A and Account B) appears in two partitions, both are stored in their respective partitions, and a `cross_account_collision_alerts` diagnostic flag (`OWNERSHIP_VERIFIED` vs `SHARED_READ_ONLY_LINK`) is recorded—never auto-merged.
WHAT "SYNCHRONIZED" MEANS PER ACCOUNT FALSIFIABLE COVERAGE METRIC

Definition of Account Synchronization & Coverage Gaps

Opening a single known conversation never marks an account synchronized. An `account_partition` reaches status SYNCHRONIZED_HEAD_TO_TAIL only when:

  1. The history index cursor has walked from the newest entry (`cursor = null`) down to a page where either `pagination.hasMore === false` or every returned `(arena_conversation_id, updated_at)` tuple matches an already-verified checkpoint in SQLCipher (`INCREMENTAL_CONVERGENCE`).
  2. Every indexed conversation stub in that account partition has been hydrated and assigned an explicit per-conversation completeness status (`COMPLETE_VERIFIED`, `HISTORICAL_HYDRATED_NO_RAW_STREAM`, or `GAP_UNRESOLVED_PAGINATION`).
  3. Any conversation where `meta.transcript.pagination.hasMore === true` (long threads with lazy-loaded earlier turns) or missing R2 workspace files is surfaced in `sync_coverage_gaps` so an LLM agent can query `sync.list_coverage_gaps` and schedule targeted turn-page backfills.

MODEL IDENTITY SEPARATION RULES NO SILENT CONFLATION

Strict Epistemic Separation of Model Labels

In accordance with the verified lessons from arena-exporter Schema 2.1, the database and UI enforce five strict identity invariants:

  • Rule 1 (Position ≠ Identity): slot_position (lane_a, lane_b) and blind_display_label (Assistant A) are structural slots. Unvoted battles display IDENTITY: UNREVEALED (BLIND SLOT A).
  • Rule 2 (Request Selection ≠ Verified Serving Backend): In Direct and Side-by-Side modes, joining requested_model_uuid to the page catalog produces an observation with evidence_source = 'request_catalog' and is_identity_verified = 0, because Arena routing/aliases can remap backend builds.
  • Rule 3 (Post-Vote Reveal Appends, Never Erases): When a Battle vote triggers an arena_reveal payload, a new row is appended to model_identity_observations with is_identity_verified = 1 and observed_at_ms. The SQL view v_effective_participant_identity selects the highest-authority non-conflicting observation while preserving the timeline of when the model was anonymous vs. revealed.
  • Rule 4 (Agent Orchestrator Explicit Null): For Agent Arena sessions where the orchestrator is not revealed, observed_model_label remains NULL with status NOT_REVEALED_BY_ARENA—never populated from tool call arguments, UUIDs, or leaderboard strings.
  • Rule 5 (Conflict Preservation): If the isolated-world DOM tab snapshot shows model label X while the network stream payload references catalog model Y (as observed in arena-exporter Sept 5–6 verification), both observations are persisted and conflict_flag = 1 is raised so the conversation is excluded from clean training cohorts until inspected.

  • Entry Gate for Local Embeddings / Classifier: Unlocked only when at least 3 verified models (`is_identity_verified = 1`) accumulate sufficient paired Battle conversations across multiple topic clusters.
