3 · Why Electron is recommended — and the exact reversal condition

3.1 Capture mechanisms outside page JavaScript (Electron)

Owning the window ≠ deeper privileges. Electron's out-of-page surface is:

  1. Main-process CDP via webContents.debugger ● Verified fact — attach to each account WebContents; sendCommand for Network.enable, Fetch.enable (selective), Target.setAutoAttach/setDiscoverTargets (exact names must be re-verified against the pinned CDP schema at spike time — do not hard-code from memory), Runtime.enable only if needed; receive requestWillBeSent/responseReceived/loadingFinished, dataReceived, WebSocket frame events, and body retrieval (Network.getResponseBody / stream takeover). All in main, not page world.
  2. Target/worker lifecycle ◐ Strong inference — CDP target discovery + Electron ses.serviceWorkers introspection cover navigation, iframe/worker/SW attach. Coverage of Arena's actual worker use is ? Unknown until spike.
  3. Session metadata + downloads ● Verified fact — ses.webRequest for header/metadata observation (not bodies), will-download for direct artifact capture without page cooperation.
  4. Isolated-world preload (secondary only) — tiny or zero privileged bridge in Arena renderers; any DOM reader runs isolated, allowlisted, and is treated as corroborating evidence, never the primary transport record.

What Electron does not give: raw socket tap, guaranteed pre-navigation attach without careful lifecycle code, or automatic stream reassembly — all must be engineered and tested.

3.2 Why this beats the alternatives for v1

  • Chromium fidelity: Arena targets Chromium-class browsers; Electron removes "does it render like Chrome?" as a variable. WKWebView cannot claim this.
  • Isolation primitive that matches the requirement: persist: partitions map 1:1 to Arena accounts with persistent cookies/storage/cache/SW state. No cross-partition leakage by design; spike must prove it.
  • Agent-maintainable: TypeScript, mainstream packaging (electron-builder-class tooling), reproducible lockfiles, machine-readable diagnostics. CEF's C++/Obj-C++ + framework bundling + version coupling is an order of magnitude harder for coding agents.
  • Materially deeper than the rejected extension: main-process lifecycle (no SW/throttle/unload eviction), early attach across navigations, target auto-attach, direct download ownership, per-partition coordinators — none depend on page-world interception surviving.

3.3 Reversal gate (binding)

Run the §20 spike to disprove Electron. Reverse to CEF iff (a) a traffic class listed as architecture-critical is missed/corrupted through maintained Electron surfaces after genuine engineering effort, and (b) a focused CEF spike with GetResourceResponseFilter demonstrably captures it with correct account attribution. If neither captures it, only then investigate invasive Chromium customization — and re-scope v1 to what is provably capturable rather than silently inferring.

6 · Product constraints, trust posture & non-goals

6.1 Hard constraints

  • Private forever: one owner, no App Store, no distribution, no hosted backend, no telemetry, no cloud analytics, no multi-user app accounts, no public updater.
  • Hardware: Apple Silicon only; dev on M3 Pro 18 GB; ≥2 Arena partitions simultaneously usable. No fabricated capacities — quotas + measurement (§23).
  • Agent-first: mainstream deps, lockfiles, explicit schemas, typed IPC, machine-checkable tests, reproducible toolchain (Phase 0).
  • Owner-data boundary: authenticated first-party reads in the owner's session ≠ access-control workaround. Undocumented ≠ bypass. Conversation URL/ID alone ≠ ownership — every op binds to a verified account/partition.
  • Auth: Arena email sign-in authoritative; owner handles OTP/MFA/CAPTCHA/redirects/popups in-app. Google OAuth/passkeys explicitly not required and must not veto a stronger browser.
  • Credentials: browser-managed cookies persist in owned partitions (required for sign-in); copied bearer tokens/cookies must never persist in DB/logs/fixtures/exports/diagnostics.

6.2 Non-goals / anti-requirements

  • No access to other users' data; no enumeration of unrelated private infrastructure.
  • No "universal transcript flattener" — battle/side-by-side/branch/revision structure is first-class (§11, §13).
  • No silent inference: partial/drifted/UI-only content is never labeled complete.
  • No heavyweight ML in v1; no embeddings until deterministic gate fails (§17).
  • No LAN-exposed privileged operations; no cloud sync of the archive.
  • No perfect-deletion promise for external backups/exports/swap — honest residual-risk table (§15).
Initial text release must handle: battle, direct-model, side-by-side, completed/stopped/failed/partial, history-opened, archived views, search/pagination when observable, selected + blind labels, votes, post-vote reveals, titles, timestamps, Arena source IDs, branches, revisions, regenerations, completion state, provenance, owning account.

7 · Process & trust architecture

Remote Arena renderers are untrusted content. Archived prompts/responses/traces are untrusted data — they can never authorize destructive actions. Privilege flows one way: owner intent in trusted UI/MCP → service layer → storage. Never the reverse.

Renderer hardening (Electron security checklist subset)

  • nodeIntegration:false, nodeIntegrationInWorker:false, contextIsolation:true, sandbox:true (global where compatible). ● Verified fact that these are documented defaults/expectations.
  • No preload in Arena views, or a minimal audited preload exposing zero privileged calls; contextBridge allowlist only, never raw ipcRenderer.
  • will-navigate + setWindowOpenHandler allowlist: arena.ai + observed auth hosts only (discovered, cataloged, owner-visible); popups for OTP/MFA/CAPTCHA hosted in same partition, never in default session.
  • ses.setPermissionRequestHandler deny-by-default; per-host grants only.
  • Every ipcMain.handle validates senderFrame origin + frame/account binding; untrusted frames get no secrets, no FS, no DB, no destructive calls.

Module & process ownership

  • Main (trusted): windows, sessions, debugger attach, coordinators, services, storage, jobs, MCP host, deletion gate.
  • Arena renderer (untrusted): remote web content only. May host isolated-world reader; no trust.
  • Diagnostics UI renderer (trusted local): app://-style custom protocol, CSP default-src 'none'-ish, no remote code.
  • MCP stdio child (trusted, separate OS process): JSON-RPC over stdio; same service imports; stderr logging only.
  • Analysis worker (trusted, constrained): separate worker/thread; read snapshots, write analysis_* only; quotas enforced.

8 · Simultaneous multi-account partition design

Not a switcher: Account A and B stay signed in and usable simultaneously. Isolation is per-account across cookies, local/session storage, HTTP cache, SW state, session/partition, pipeline, auth authority, provenance, sync state, and destructive scope. Failure in one must not rebind or corrupt the other.

// Representative — account partition descriptor (TS, main-process only)
interface ArenaAccountPartition {
  accountUuid: string;              // internal UUID (PK); stable local identity
  partition: `persist:arena-${string}`; // UUID-suffixed; never email-derived
  storagePath: string;              // ses.getStoragePath() for diagnostics (no secrets)
  webContentsId: number;            // bound view; validated on every IPC/CDP event
  debuggerAttached: boolean;
  auth: { state: 'SIGNED_IN'|'SIGNED_OUT'|'EXPIRED'|'CHALLENGE'|'UNKNOWN';
          verifiedArenaUserRef?: string; // opaque, sanitized; re-verified on drift
          lastVerifiedAt: string; needsOwnerInteraction?: string };
  capture: { mode: 'RECORDING'|'PAUSED'|'STOPPED'; coordinatorId: string; queueDepth: number };
  sync: { cursorId: string; checkpoint: SyncCheckpoint | null };
}
// Invariants: (1) every observation carries accountUuid; (2) uniqueness scopes include
// accountUuid — identical text or equal Arena source IDs across accounts NEVER merge;
// (3) partition→account binding is immutable; identity change halts authority pending re-verify.

Isolation rules

  • Partition names: persist:arena-<internal-uuid>. ■ Recommendation No emails / handles in partition strings, paths, or logs.
  • Each account gets its own Session, view, debugger attachment, coordinator, sanitizer instance (shared code, separate state), sync cursor, and job queue.
  • CDP/session/download events are tagged at ingress; mismatched webContentsId/session ⇒ drop + diagnostics.capture_gaps.
  • Sign-out/expiry/CAPTCHA/identity-change pauses that account's capture authority + sync; other account continues. Rebind requires explicit re-verification, never auto-heal by text match.

Auth authority per account

  • Arena's own UI is authoritative; app never fabricates sessions. Email flow + OTP/MFA/CAPTCHA handled owner-driven in the correct partition's popups/redirects.
  • Authority = (partition session valid) + (observed Arena identity matches bound verifiedArenaUserRef) + (no active challenge). Any failure ⇒ NEEDS_OWNER_INTERACTION scoped to that account.
  • Native sync replay may transiently reuse that partition's credentials (memory only); copied secrets never touch disk (§15).
  • Provenance triple on every record: (accountUuid, partition, authEpoch); epoch bumps on sign-out/expiry/rebind.

Sanitization (fail-closed, at ingress)

  • Strip before durable write: authorization, cookie/set-cookie, CSRF secrets, passwords, OTPs, OAuth codes, bearer tokens, signed-URL query params, fingerprinting headers, unrelated private fields.
  • Retain: sanitized URL family, method, status, timing, sizes, sha256(sanitizedBody), parser-relevant fields, account/provenance.
  • Keep minimal raw-evidence window (bounded bytes, in-memory ring + encrypted spill) for parser debug/drift/reparse; sanitizer failure ⇒ reject durable raw, keep hash + gap marker.
  • No credentials in DB, logs, fixtures, exports, diagnostics. Ever. Tested (§20).

Drift detection

  • Each adapter declares expected shape + required fields + version. Unknown fields ⇒ preserve as unknown_observation (sanitized), mark adapter DEGRADED, emit diagnostics.drift.
  • Missing required field / type break / new transport for same op ⇒ UNSUPPORTED for that op only; rest of pipeline continues.
  • Catalog exposes first/lastObservedAt + event counts so agents can see "Arena changed Tuesday" without reading traffic.
  • Reparse: sanitized observations are immutable-ish; parser upgrades re-run deterministically and record new adapterVersion without rewriting history.

10 · Live-capture architecture

Transport coverage (all Arena specifics Unknown)

  • XHR/fetch + streamed fetch: requestWillBeSent/responseReceived/dataReceived/loadingFinished + body retrieval; reconstruct chunked/SSE-style streams where Arena uses them; record responseReconstructionDigest.
  • EventSource: covered as stream class; parser distinguishes heartbeat vs. payload frames.
  • WebSocket: frame events if observed; no assumption Arena uses WS. Spike must report "WS observed: yes/no + op families".
  • Workers/SW: auto-attach + SW introspection; any target without an attached session ⇒ explicit UNOBSERVED_TARGET gap, never silent.
  • Navigation: capture survives SPA transitions + full navigations; request→navigation→response correlation preserved.

DOM/UI evidence (secondary)

  • Minimal isolated-world reader (or none in v1 if network evidence suffices): turn boundaries, visible model labels, vote/reveal affordances, error/stopped banners.
  • Stored as DOM_HINT observations with selector-version + timestamp; reconciler may corroborate but never fabricate transport bytes.
  • UI-only reconstruction is an explicit completeness state (UI_ONLY_RECONSTRUCTION), visibly weaker than LIVE_CAPTURE.
  • Drift in Arena markup degrades hints only; transport capture must not depend on selectors.

11 · Completeness, reconciliation & idempotency

Never confuse "the model finished" with "we saw everything." Completeness is a per-revision state machine with provenance; reconciliation merges order-free, duplicate-tolerant observations without overwriting stronger history with weaker inference.

StateMeaningAllowed transitions (examples)
COMPLETEDNormal finish and fully observed (final frame + digest verified).→ CONFLICTING_EVIDENCE if later evidence disagrees.
STOPPED_BY_OWNEROwner stopped generation; partial content explicitly marked.Terminal for that revision; new revision on regenerate.
MODEL_BACKEND_FAILUREArena/model error payload or error banner observed.→ COMPLETED only via distinct retry revision.
NETWORK_INTERRUPTEDTransport cut (offline, navigation, crash) mid-stream.→ BACKFILLED if history replay later completes it (provenance preserved).

12 · History synchronization (backfill) — separate gate, honest "synchronized"

Backfill is not live capture. Preferred path ◇ Hypothesis to test: stable authenticated owner-history LIST + DETAIL reads, proven non-mutating and account-bound in an owner-session gate. Fallback: automated UI traversal + capture with visibly weaker guarantees. Opening one known conversation proves nothing.

Adapter strategy

  1. Discover candidate LIST/DETAIL ops during normal history browsing (cataloged, sanitized).
  2. Prove in backfill gate: ownership binding, pagination, detail retrieval, absence of mutation (state-diff before/after across list/detail/repeat/overlap; no POST-side-effects-by-GET assumption), checkpoint/resume, overlap handling, isolation, expiry/challenge/rate-limit behavior.
  3. Promote to REPLAY_VERIFIED sync adapter only after gate passes per account family; any drift demotes to DEGRADED and pauses sync for that account.
  4. Fallback to UI traversal (paginated scroll + capture + DOM hints) with completeness capped at UI_ONLY_RECONSTRUCTION/BACKFILLED(via-traversal) and explicit coverage gaps.

Also supported: future official export, user-imported archive (weak provenance, quarantined until verified), future documented API — all as adapters, never as silent merges.

"Synchronized" — precise per-account meaning

Account A is Synchronized iff:

  • LIST adapter REPLAY_VERIFIED at version V; full keyset walk completed (cursor exhausted:true) with overlap/repeat handling;
  • every listed conversation has DETAIL fetched at version V or an explicit per-item gap (auth-expired | rate-limited | drifted | deleted-remote | conflict);
  • live-capture overlap window reconciled (no double-count, no loss);
  • sync_state exposes: listedCount, detailedCount, gapCount, gaps[], adapterVersions, completedAt, coverageNotes.

Anything else is Partially synchronized (N/M + gaps) — the MCP/GUI must show gaps, not a green check.

Transactions / crash / migration / reparse

  • Ingest in one SQLite transaction per batch: observations → normalized upserts → FTS → cursors. Crash ⇒ rollback; idempotency keys make replay safe.
  • Migrations: versioned, forward-only, tested with fixtures; backup before migrate; downgrade = restore backup (documented).
  • Parser upgrade ⇒ new adapterVersion; background reparse over source_observation; results add revisions/observations, never rewrite observed_at/provenance.
  • Backup/restore: online backup API to encrypted copy; restore verifies HMAC/page integrity + schema version + FTS consistency check.

Deletion cascades & FTS/blobs

  • ON DELETE CASCADE: account → conversations → branches → turns → participants → revisions → artifacts(refs) + identity/vote rows. source_observation scoped delete by account/conversation.
  • FTS rows deleted in same transaction; blobs dereferenced then securely deleted (unlink + best-effort overwrite note; no promise against forensics/backups).
  • Sync checkpoints/dedup markers for deleted scope are purged; re-sync after delete re-fetches as new provenance (surfaced, not silent).

15 · Encryption, local-data exposure & deletion

15.1 Key hierarchy ■ Recommendation

  1. Generate 256-bit random archive key via SecRandomCopyBytes at first run; store in macOS Keychain (kSecClassGenericPassword, kSecAttrAccessibleWhenUnlockedThisDeviceOnly-class protection, access-group locked to app identity).
  2. Open SQLCipher with raw binary key (PRAGMA key = "x'…'"), not a human passphrase. ● Verified fact SQLCipher supports raw-key mode + per-page IV + HMAC.
  3. Derive blob/data subkeys via HKDF-SHA256(archiveKey, context) per purpose (db-hmac handled by SQLCipher; blob-aead, export-wrap, checkpoint-mac app-side).
  4. Never persist archive key in config/logs/fixtures/exports/diagnostics. Memory: lock + zeroize where possible; acknowledge renderer/OS residual limits honestly.

SQLCipher posture

  • PRAGMA journal_mode=WAL; PRAGMA temp_store=MEMORY; (WAL + journal pages encrypted; temp files memory-only — both ● Verified fact design requirements).
  • FTS5 index inside the encrypted DB (encrypted pages), not as sidecar plaintext. Large artifacts as encrypted blobs (§15.2), not as ever-growing TEXT/BLOB rows.
  • Cipher knobs (page size, KDF iters) left at maintained defaults unless measurement justifies change; record effective cipher_settings in DB header table for diagnostics.

17 · Deterministic local analysis (v1)

All analysis runs locally, transparently, reproducibly. v1 = deterministic statistics over the normalized corpus. Every profile run records its cohort definition + sample counts + preprocessing hash; results are boring-on-purpose so later ML claims can be judged against them.

Profile families (v1 inventory)

  • Length: response/paragraph/sentence/code-block chars + tokens (local tokenizer version pinned).
  • Lexical: type-token ratio, hapax share, top n-grams (1–4) with stopword policy stated.
  • Form: Markdown habits (headings, lists, tables, bold/code spans), code/prose ratio, citation patterns.
  • Discourse: openings, transitions, conclusions, qualifications, hedging, refusal/apology, uncertainty markers (lexicon versioned, editable, disclosed).
  • Punctuation/casing: sentence-terminal mix, Oxford-comma rate, header-case policy.

Stratify by: identity evidence (observed only — never inferred-as-truth), mode, prompt type/topic/language, date, conversation context, account (sampling disclosure only).

Confounders (must appear in every report)

  • Single-owner selection bias; repeated prompting habits; topic skew.
  • Arena hidden prompts, model system prompts, decoding params, tools/routing/aliases.
  • Temporal model updates; safety layers; Arena post-processing/normalization.
  • Truncation/stopped/partial revisions excluded-or-flagged, never silently pooled.
Empirical gate for embeddings/ML: add local ML only when a pre-registered deterministic baseline demonstrably fails a falsifiable task (e.g., calibrated authorship separation with held-out cohorts) and a leakage-resistant pilot shows ML closes the gap. Cost, reproducibility, and provenance burden must be re-approved.

18 · Later work: fingerprinting experiments & modalities

18.1 Stylistic fingerprinting = hypothesis, never proof

  • Requires: held-out conversations; leakage-resistant splits (branches/near-duplicates same-split); prompt/topic controls; negative controls (same-model-different-topic; different-model-same-prompt); calibration + unknown-class rejection; temporal validation (train past → test future); reproducible preprocessing hash.
  • Observed-vs-inferred identity separation preserved end-to-end; inferred labels quarantined in identity_observation(kind=INFERRED_STYLISTIC) with model + calibration.
  • No universal minimum-N invented here — empirical power/stability analysis decides continuation per experiment.
  • Failure modes disclosed: alias/route churn, hidden-prompt shifts, post-processing, owner-style entrainment.

18.2 Modalities after text (extension points, not a v1 framework)

  • Shared primitives: source_observation + artifact(blob_ref) + provenance + adapter versioning. Each modality adds a narrow adapter, not a universal content graph.
  • Search/citations; Arena Code/web-dev files + previews + DB metadata + tool events; images + EXIF-ish metadata; video/workflow artifacts; agent sessions + tool traces; uploads + derivatives.
  • Each adapter declares: transports, completeness states, retention/blob policy, PII handling, drift signals, backfill availability (often "none" — say so).

Process boundaries: apps/desktop(main) owns browser+capture+storage+sync; MCP is a stdio child importing domain/storage/sync/analysis; analysis runs in a worker with read-snapshot + analysis_*-write-only access.

23.2 Minimum supported macOS ■ Recommendation

Minimum: macOS 26.0, Apple Silicon only. Dev/target: macOS 27 (current machine).

  • Private single-machine app: no reason to carry N-3 test matrix; N-1 (26 ← 27) minimizes QA while keeping a fallback boot.
  • Recent-major pin keeps Electron/Chromium, Keychain (SecRandomCopyBytes, device-only accessibility), file-protection, and notarization behaviors modern without chasing the dev-major exclusively.
  • Apple Silicon only: no Intel codepaths, no universal-binary native-module matrix; SQLCipher/prebuild complexity halved.
  • Revisit only if Electron drops 26 or a required API demands 27 — then minimum becomes 27 with a note, not a silent drift.

23.3 Resource quotas (measured, never fabricated)

  • Per-partition renderer memory, main-process memory, capture queue (count + bytes), DB growth, blob bytes, sync throughput — all observed via diagnostics, with configurable caps + backpressure (pause-capture-with-gap, slow-sync, spill-then-drop-with-gap).
  • Concurrency defaults: 2 live partitions + 1–2 sync jobs; traversal fallback is strictly serial per account. No benchmark numbers are asserted in this plan.
