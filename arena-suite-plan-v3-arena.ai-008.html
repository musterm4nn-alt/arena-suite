The decision in one paragraph

Build a private, Apple-Silicon-only Electron shell with two or more concurrently live WebContentsView sessions, each in an immutable persistent partition. The main process owns CDP attachment before navigation, per-session network metadata, download routing, authority checks, and scheduling. A single small Swift process owns SQLCipher, Keychain, artifact encryption, and transactional storage; TypeScript services own capture adapters, sync, MCP, and deterministic analysis. The primary history strategy is replay of verified owner-scoped reads through the correct Chromium session. Until verified, use supervised UI traversal and label coverage partial. CEF replaces the browser layer only if a required early/worker/stream observation cannot be made reliable through Electron’s maintained APIs.

What v1 actually delivers

Battle, Direct, and Side-by-Side text; stopped and failed attempts; branch-aware offline transcripts; identity evidence; per-account history sync; encrypted search, export, deletion, diagnostics, and local profiles. Every local GUI action has the same service-backed MCP operation.

What this plan does not promise

Exact serving model builds, hidden reasoning, undisclosed turns, complete historical coverage without an enumerable representation, perpetual adapter compatibility, or a measured memory footprint. Google OAuth and passkeys are not release requirements. No extension is the target.

Electron versus CEF: the consequential difference

Why Electron first

Fewer native seams to maintain.

It exposes account partitions, WebContents lifecycles, CDP sessions and download items directly to the same TypeScript services used by the GUI and MCP. There is no MV3 service-worker lifetime to preserve, no extension install, and no native-messaging archive bridge. One small Swift storage process avoids npm SQLite/Keychain ABI risk.

What CEF genuinely adds

A native HTTP response filter.

An account-context handler can identify a worker request even with no page frame and copy body chunks while passing them through unchanged. That can remove CDP buffer/late-body dependence. However, HTTP filtering is not a universal socket, service-worker cache, or UI semantic observer; CDP and account-aware reconciliation still remain.

Recommendation Do not run both engines in production. Both can own downloads (will-download/DownloadItem versus CefDownloadHandler), partition simultaneous accounts, and ship a Chromium runtime. CEF need not use more resident memory than Electron, and Electron is not “lighter” by assertion; compare process sets and working behavior. Electron saves C++ lifecycle and packaging work; CEF offers a more direct HTTP body path. The decisive reversal is a required Arena stream or worker path that Electron cannot observe without mainly patching the page, but CEF can observe with maintained response filters/CDP. Only then replace the browser module and rerun all trust gates.

03 / The first engineering objective

Observe. Sanitize. Reconcile.

Discovery is a maintained subsystem, not a one-off DevTools exercise. Inventory broadly; retain content narrowly.

Attach before the first meaningful byte

  1. Create the account context first. Allocate a random partition UUID, persistent Session, authority controller, capture queue and read scheduler. Install a single multiplexing webRequest listener per event before creating any page. Electron uses only the last listener for each event; modules must not overwrite each other. All callbacks are bounded and promptly continue permitted traffic. [06]
  2. Create a blank, sandboxed WebContents. The application factory assigns the partition and registers lifecycle/target handlers. Attach webContents.debugger; enable required Network/Page/Runtime capabilities and recursive Target.setAutoAttach with flat sessions. New eligible targets wait at startup until minimal observation is ready, then receive Runtime.runIfWaitingForDebugger. A watchdog releases or closes stalled targets and marks a gap; observation must not deadlock login.
  3. Do not confuse page targets with the browser target. Related-target auto-attach is not proof of global service-worker coverage. Probe native Target.attachToBrowserTarget access in the pinned Electron runtime; it is experimental and not assumed available from a WebContents debugger. Browser-only Target.autoAttachRelated is used only if that probe succeeds. Otherwise attach only provably associated targets; session service-worker inventory exposes missing coverage, not bodies. No unauthenticated remote-debugging port is enabled. [07][08]
  4. Prove target-to-partition mapping. Maintain parent/opener/child relationships and compare service-worker registrations with session-scoped inventory. Browser-context IDs, where present, must be mapped through controlled app-created targets; the same origin, script URL, or apparent target title across A and B is insufficient. An orphan target remains unbound: no transcript body retention or replay authority. Required Arena worker traffic that cannot be bound and attached early falsifies Electron for that release.
  5. Open Arena only after the observer barrier. Bootstrap top-level pages on about:blank and release navigation after successful probes. Intercept popups before creation, force the opener’s partition, and prime new WebContents. For auth popups where recreating a request would lose POST data/opener semantics, allow the browser-managed flow with an explicit observer-gap interval rather than fabricate complete capture. Test popup timing. Unsupported conversation popups cannot count as full v1 coverage.
  6. Handle navigation as a lifecycle event, not an archive reset. Requests remain bound to their initiating target, loader, account epoch and attempt even after URL changes. Reattach new targets, preserve old in-flight mappings, and detect renderer crashes, debugger detach, discarded views and app sleep/wake. Opening DevTools can detach Electron’s debugger; the diagnostic UI therefore uses sanitized app views, and an explicit DevTools action first pauses the affected recorder. [04]

Hypothesis to test The documented CDP primitives can be made early enough and correctly scoped for Arena’s required traffic. Test existing service workers at app restart, new versions, dedicated/nested/shared workers, out-of-process frames and popup navigation in two partitions. Being able to see one worker after it starts is not a passing early-attachment result. If only a page monkey-patch can recover required data, the selected architecture fails its capture-depth gate; it does not quietly become the old recorder inside a new window.

Do not turn an observer into a proxy by accident

Fetch.takeResponseBodyAsStream is not a passive tee: the protocol says the request cannot simply continue afterward; the client must cancel or provide the body. Do not make it the default live-capture path. Likewise, do not turn off service workers, disable cache, strip CSP, or rewrite origins merely to make tests pass. Any intervention changes the workflow under measurement. Current durable-body documentation warns about legacy enable-ordering deadlocks; probe Network.configureDurableMessages and use a tested watchdog/release sequence, rather than blindly awaiting enableDurableMessages on a paused target. The sanitization boundary comes before persistence

  • In the trusted event boundary, drop auth/account/challenge bodies, headers, cookie values, bearer material, passwords, OAuth codes, CSRF secrets and signed query/fragment values. Never serialize a raw CDP/WebRequest event, HAR, netlog, console message, error object, or browser storage dump.
  • Known conversation adapters allowlist safe fields; scan all retained text—including nested encoded JSON strings—for known session-secret values held only in memory and recognizable secret patterns. Replace redactions with typed spans and record their effect on textual completeness. Preserve accepted transcript bytes otherwise; retain normalization rules separately.
  • Unknown payloads produce bounded shapes, type counts, lengths, safe enum samples and schema digests. Unknown property names can themselves contain private values: retain allowlisted names or salted/keyed hashes, not arbitrary raw keys. Investigation mode is an owner-enabled, account-scoped, bounded in-memory view; it does not create a credential-dumping “save all” switch.
  • Parser failures retain only a controlled error code, adapter/version, safe schema path, numeric offset/length and evidence handle. Exception messages and excerpts are unsafe by default. Oversize/depth/decompression limits fail closed for that payload, preserve diagnostic counters, and mark a gap.
  • Sanitized semantic evidence may be retained encrypted for 30 days or the evidence quota, whichever comes first. Catalog aggregates and provenance assertions remain; reconstructive payloads expire. Diagnostics default to no conversation text. An explicit evidence-read tool can return approved excerpts as untrusted data, never raw wire data.

Honest limit: no general scanner can prove that arbitrary user prose, source code or a binary image contains no novel secret. The hard guarantee is never retaining credential-bearing protocol fields/copies; transcript scanning is defense in depth, with redaction warnings and unsupported binary retention disabled. Do not claim general anonymization or byte-perfect capture after redaction. This limitation must be visible in diagnostics and exports.

Reconstruct attempts, then project conversations

Use an observation envelope keyed by (app_run, partition, authority_epoch, target_session, request_id, attempt_id), with account ID assigned by the host registry—not remote data. Decode UTF-8 incrementally, carry incomplete characters and framing boundaries across chunks, and version each framing adapter. Parse SSE/JSON-line/protocol frames only when observed, not from an assumed Arena convention. Apply explicit event sequence/source-node IDs where available; de-duplicate repeated source events within their account, attempt, branch and payload digest. Missing sequence numbers remain missing. Identical text may be intentional repetition.

Keep generation attempts separate from logical turn revisions. A rejected/failed request is an attempt with an outcome, not an invented assistant message. Reconnects may join only through verified source IDs and protocol resume evidence; otherwise they are alternative attempts awaiting reconciliation. A full-body or history snapshot is a separate observation to compare against the streamed projection, not another batch of text to append. Snapshots are authoritative only for their represented fields and scope; a newer snapshot cannot erase a stopped attempt or a known branch merely by omitting it.

Prompts create turns; editing a prompt creates a revision/branch edge when supported; regeneration creates another assistant attempt/revision. Battle/Side-by-Side retain a comparison round with positions, participant IDs and response nodes. Use source graph edges when present. DOM order can supply a provisional display path, marked inferred; it cannot fabricate hidden branches. Titles, timestamps, selected model labels, visible votes, reveal events and completion signals each carry their own observation source, applicable turn range and confidence. Capture opened history, search pagination and archived-history views as distinct workflows, not aliases presumed equivalent.

04 / Identity is a boundary

Two accounts. Zero inheritance.

Partition isolation is necessary. Account authority and conversation ownership must still be established independently.

Immutable partitions, revocable authority

Create persist:arena.<random-partition-uuid> once per owner account slot; never use email, a conversation ID, or the default session as its key. Keep one or more live views per slot and two slots concurrently active. Each Session owns cookies, HTTP/cache state, local storage, IndexedDB, CacheStorage and service-worker registrations. SessionStorage remains page-scoped inside that partition; popups inherit only their opener’s partition. Set distinct code-cache directories and download/capture/sync contexts. Chromium may share executable code, GPU or network-service processes; those are not separate security principals, and no per-account OS process isolation is promised by partitions alone.

The local account_id is an immutable UUID, distinct from partition_id and the currently authenticated Arena subject. A partition starts unbound. Observe the account identity through Arena’s actual signed-in account UI and, if discovered, a session-scoped identity response. A stable authenticated subject is preferred; a verified account UI identity may support a lower-confidence binding if no such response exists. Owner-chosen aliases are display names, not proof of authentication. Mask email in default diagnostics; preserve necessary owner identity only in the encrypted account record.

unbound→authenticating→verified→suspended→reauth_required

Issue an in-memory authority lease containing account UUID, partition UUID, observed subject digest, monotonically increasing epoch, evidence ID and expiry/recheck deadline. Recheck before each replay batch and after navigation/login-related transitions; known identity changes, sign-out, ambiguous account UI, 401/403, auth redirects or unresolved challenges suspend that lease immediately. A token refresh that preserves a verified subject may renew it; an unexplained subject change may not. Never infer ownership from a token-shaped string.

Requests and callbacks capture their initiating lease immutably. Verify it again at commit and before each destructive/sync operation. When A signs out, reject later callbacks under A’s revoked epoch, discard transient credentials, abort A’s app-issued requests and mark affected attempts partial. Already committed evidence retains its original scope. B’s lease, stream queues and checkpoints are unaffected. A partition that signs into a different account is retired and its observations quarantined; create a new partition for that subject rather than relabel old records. If a same-subject reauthentication cannot be proven, require a fresh binding and preserve the old archive separately.

  • For mutable offset pagination, capture an observed high-water mark if one exists, overlap boundary pages, and perform a reconciliation pass.   • Live capture and backfill write through the same account-scoped reconciler. Failure policy and safe native requests

Use a per-job abort controller and per-account auth mutex. Respect verified Retry-After values and use bounded exponential jitter; initial policy is three retries for retryable transport/429/5xx failures, then backoff or a resumable failure. Never retry generation/vote/delete as history reads. 401/403, challenge HTML, unexpected redirect or account change revokes/suspends the affected lease without a blind retry loop. Schema drift disables the specific operation adapter; other verified reads may continue only if their admission assumptions still hold. Suspected mutation stops that account’s entire sync pending investigation.

ses.fetch uses Chromium’s stack, unlike Node’s global fetch; the default-session shortcut is forbidden. Its documentation also notes limitations in returned Response URL/type values. Therefore enforce redirect/origin policy at the request/session boundary and explicit redirect handling, not by trusting response.url alone. Native response provenance comes from the executor’s immutable job/lease, not a heuristic match to CDP traffic. Refresh never moves to another account’s “working” session. [05]

A precise definition of synchronized

For account A, adapter V and declared surfaces S: every owned ID enumerated during this run has a committed supported detail representation, a verified unchanged revision, or a named unresolved gap; pagination reached its evidenced boundary; no pending work is concealed. Call it completed only when the declared scope has no unresolved required gaps. Return completed_with_gaps otherwise. Historical exhaustiveness remains unknown unless a trustworthy enumeration contract supports it—even after repeated passes stabilize.

If there is no reliable listing endpoint, build a worklist from owner-visible history/search/archive results and already-established owned IDs. A dedicated sync view traverses bounded pages, expands visible turns and records which branches were opened. If no stable pagination or complete representation exists, support incremental observed-history accumulation, imports and manual selection; display unbounded unknown past coverage. Opening one known conversation is never a substitute for the full-history gate. Optional automatic sync is off by default and enabled separately per account, with explicit surfaces, budgets and pause rules; “Sync now” remains available for any selected accounts.

Transactions and crash recovery

  • A short write transaction inserts an accepted sanitized observation, updates the affected projection and field-evidence joins, increments entity version, updates encrypted FTS5 and advances the durable acknowledgment. Batch incremental frames for throughput, but only advertise text as durable after commit. A crash can lose uncommitted in-memory bytes; recovery marks that interval rather than inventing them.
  • Write artifacts to ciphertext-only temporary objects, authenticate chunks, fsync and atomically rename before the transaction marks them available. The DB/file boundary is a small two-phase manifest: pending → available. Startup reconciles pending objects, deletes unreferenced ciphertext and marks missing/corrupt files unavailable without discarding the conversation.
  • Use WAL for the single writer plus short reader snapshots; bounded busy retry prevents a long search from blocking capture. SQLCipher encrypts page data in WAL and rollback journals, not every conceivable temp file. Keep temp stores in memory and verify actual build options. [18]
  • After abnormal shutdown, mark open capture attempts observer_interrupted, keep their bytes and restart jobs as paused. Verify cipher/SQLite integrity and FK constraints, recheck identity before networking, and never auto-migrate/repair by deleting the only copy.
  • Migrations are numbered, transactional where possible, with pre-migration encrypted backup and schema/version checks. A newer unknown schema opens no write connection. Reparse retained evidence into shadow projections, compare diffs, then promote transactionally; retain parser lineage and mark fields unrecomputable after evidence expiry.

Encryption and keys

Recommendation Generate a 256-bit random archive master key with the OS CSPRNG. A signed Swift broker stores it as a non-synchronizing Keychain item; the default design uses the data-protection Keychain with unlocked/device-only protection when the locally signed build supports it. Validate signing, entitlements and key access during bootstrap; if that configuration is unavailable, use a deliberately configured login-Keychain item restricted to the stable signed broker and disclose its different lock semantics. This fallback preserves Keychain protection, not a false device-only guarantee. Never write a key file or use a database password embedded in source. Apple’s device-only attribute explicitly does not migrate to another device. [23]

Derive purpose-separated DB and artifact-wrapping keys using CryptoKit HKDF; supply the DB key in SQLCipher’s raw-key format through the C API before any database query. Verify PRAGMA cipher_version, an encrypted schema read, wrong-key failure, and FTS5 availability. If a packaged SQLCipher build lacks needed options, compile a pinned official SQLCipher source amalgamation with the documented codec/init/shutdown, thread-safety, FTS5 and in-memory-temp flags in Swift’s C target. Do not substitute stock SQLite. The package route avoids Electron ABI rebuilds but still needs binary checksum, arm64 slice, load/link and license checks. [16][17]

For large artifacts, use CryptoKit AES-GCM in a small versioned chunk container: a fresh random per-object key, unique per-chunk nonce derived from an object-specific nonce prefix and strictly increasing counter, authenticated object UUID/account/version/chunk index, and an authenticated final manifest containing total bytes, chunk count and whole-content digest. Never reuse a key/nonce pair or accept a truncated container as complete. Store wrapped object keys and metadata inside SQLCipher; random filenames expose no conversation names. Encrypted thumbnails, indexes and derived objects use the same scheme. No plaintext vector/search index exists alongside the database. [24]

On explicit archive lock, close DB handles, cancel/pause jobs, clear local UI/search caches, zero Swift key buffers where practical and close or blank archive views. Stop accepting capture while locked; the owner may choose to keep remote Arena browsing visible but unrecorded. OS screen lock triggers archive lock by default. Keychain protection does not remove keys already resident in memory without this lifecycle work.

07 / The primary interface

Built to be operated by agents.

One application service layer, two clients: the small local GUI and an actual scoped MCP server. No essential local workflow is GUI-only.

Transport, connection model and authorization

Use MCP stdio. An owner-registered client launches a small compiled TypeScript/Node relay, arena-archive mcp, which connects to the single running app through a Unix socket in a 0700 control directory (socket and client capability files 0600). If absent, the relay can launch the approved app binary once; it does not launch another browser per MCP connection. The main process hosts the service registry; the relay uses the official SDK for schemas/framing. Only MCP JSON-RPC goes to stdout; stderr contains sanitized diagnostic codes, not raw request/response bodies.

The consulted v2 SDK and 2026-07-28 specification use server/discover, per-request metadata and explicit state handles; do not mix their semantics with the older initialize-based spec. Pin and test SDK/client compatibility. Use tools/list and resources/list/read; use app job polling as the durable baseline, with supported subscription/progress notifications as an optimization. A client lacking this version receives a deterministic incompatibility diagnostic or a separately tested legacy adapter—not guessed wire behavior. [19][20][21]

Local client registration grants an explicit role, archive/account selection and operation classes. A relay authenticates with a random app-issued capability from the protected control configuration; the app checks it on every call. clientInfo, an account UUID and a model-written “approved” field are not authorization. Default grants expose metadata/diagnostics only; transcript/artifact reads and plaintext export require separate owner-approved scope. Revocation closes clients and cancels relevant pending permissions. No HTTP listener, public CDP port, arbitrary SQL, shell, cookie inspection, raw JavaScript evaluation or free-form filesystem tool is exposed.

Filesystem permissions and capabilities protect against remote pages and unapproved local clients; they do not isolate malicious code already running as the same macOS user. Run the operational LLM without arbitrary archive-file writes or OS Accessibility privileges. A development agent with unrestricted shell/signing-key access can bypass application-level policy by changing/deleting files; that is a separate trusted role, not a claim this protocol can solve.

Shared schemas and result rules

  • Scope always contains archive_id and explicit account UUID(s). Live/browser/sync calls additionally bind partition ID and expected authority epoch. No implicit “current account,” even when a GUI tab is selected. Offline reads do not require a currently live Arena login; their capture provenance remains unchanged.
  • Every tool declares input/output JSON Schema with unknown properties rejected, stable IDs, limits and effect annotations. Discovery reports feature availability, required permissions, adapter compatibility and reasons for unavailable operations. An unavailable future modality remains advertised as unsupported, not a tool that silently returns an empty success.
  • Tool results use structuredContent plus a compatible serialized content block when required by the SDK. Archive text/excerpts live under untrusted_data, not operational recommendations. Generated recovery steps come from fixed app error mappings, never interpolated from a transcript or raw server error.
  • List queries use opaque cursors bound to query digest, explicit scope and a snapshot version; default 50/max 200 records and a bounded byte budget. Long turns have offset/continuation handles and an explicit incomplete-page flag. Cursor expiry returns CURSOR_EXPIRED; it cannot drift to another account or silently skip results.
  • Long-running calls return a durable job handle promptly. Job output includes state sequence, scope, per-account progress, known/unknown totals, checkpoints, gaps and retryable error categories. App jobs outlive a relay disconnect; an owner can inspect/cancel them from another authorized client or GUI.
  • Use idempotency keys for sync/export/import/analysis/deletion start and commit, bound to client, tool, scope and argument digest. Same key/different arguments is a conflict. MCP cancellation cancels an in-flight request; cancel an already acknowledged background job with jobs.control. Both paths have explicit behavior.

What one heavy user’s corpus can and cannot support

Defensible

“Among these observed, completed English Direct answers to my coding prompts in this period, this revealed label used more fenced code.” Descriptive tendencies, within-prompt paired comparisons where available, drift within the observed corpus, and representative examples are useful.

Not defensible without more evidence

“This is the model’s inherent style,” “these providers share weights,” “the hidden model is X,” or population rankings from unmatched prompts. Selected names do not prove serving builds; statistically separable responses do not prove authorship.

Selection bias comes from this owner’s tasks, preferred models, survival of retained conversations, modes and voting decisions. Confounders include prompt/topic/language, related conversation history, hidden system prompts, decoding settings, tools and safety layers, aliases/routing, temporal backend changes and Arena post-processing. Code-heavy vs prose-heavy tasks can overwhelm model differences. Prefer matched prompts/rounds and time windows, report per-account cohorts before combined views, and show effective independent conversation counts. Do not infer quality, truthfulness or hidden reasoning from formatting metrics alone.

Embeddings and local ML: not selected for v1

Embeddings may help topic matching or semantic retrieval, but can obscure preprocessing, add large weights/native dependencies and compete with Chromium for the M3 Pro’s shared memory. They are not needed to count structure or characterize observed phrasing. Reconsider only if a predeclared benchmark shows materially better useful retrieval or confounder control than FTS5 + deterministic topic strata, without degrading two-account capture.

If admitted later: choose one maintained Apple-Silicon-capable runtime and one license-compatible model; acquire weights explicitly once, pin repository revision and byte hashes, record tokenizer/pooling/quantization/context limits and normalization, encrypt derived vectors, and disable networking after setup. Record runtime/weight/preprocessing versions with every run. Reject a package whose offline behavior, provenance, reproducibility or memory budget cannot be verified. This report does not claim a model/runtime benchmark or select an untested embedding package in advance.

Similarity experiments need an abstain option

  1. Predeclare the question: similarity to this labeled reference corpus, not proof of model identity or shared training data. Keep inferred labels in analysis-only tables with uncertainty and unknown-class output.
  2. Split by held-out conversations and clusters of near-duplicates, prompt templates and related branches/regenerations; keep paired rounds/edits together. Add a temporal holdout. Fit vocabularies, scalers, feature selection, topic matching and thresholds only on training data; never leak test-derived preprocessing.
  3. Control prompt/topic/mode/language and conversation depth. Compare response-only stylometry with prompt-only/topic-only baselines, a shuffled-label baseline, formatting-only baseline and unrelated held-out labels. If prompt features explain the result, model fingerprinting has not been demonstrated.
  4. Use a validation set for probability calibration and abstention thresholds; report held-out confusion, calibration error, unknown-class false acceptance and performance by cohort. Include deliberately unseen labels, changed time periods and uncertainty in ground-truth labels.

An improved chrome.debugger extension could share some CDP primitives; the claimed gain is the app-owned lifecycle/session/file path over the actual baseline, not exclusive ownership of CDP.

Fixtures and evidence are three different things

Synthetic harness evidence

A local fixture server generates known split bytes, malformed frames, aborts, reconnects, cache/SW behavior, duplicate events, two account-like cookies, graph revisions and misleading labels. Expected digests/graphs are exact; fake secrets are safe sentinels. This proves harness/parser behavior, not Arena compatibility.

Platform and owner evidence

Documentation proves API intent. Runtime probes prove this pinned build’s behavior. Owner-session acceptance proves a specific real Arena workflow, under a named account/partition, observed time and adapter digest. Keep those evidence types distinct in every gate report.

Owner-session fixtures contain only reviewed sanitized semantic payloads and necessary UI assertions; no account tokens, headers, auth screenshots, full URLs, unrelated fields or raw netlogs. Use local synthetic text for repeatable tests. Record withheld/unknown evidence explicitly. Golden files must carry account pseudonyms, adapter/sanitizer versions and expected gaps; never “fix” a regression by updating goldens without a documented source explanation.
