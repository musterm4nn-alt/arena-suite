Private Arena Conversation Archive

Architecture & implementation plan for a dedicated-browser macOS app that records the operator's own Arena conversations (battle, direct, side-by-side, Code Arena surfaces) into an encrypted, offline, branch-aware archive. Minimal diagnostics-first GUI; a local MCP surface is the primary interface. Simultaneous multi-account isolation is a hard requirement.

Winner: Electron + Chromium (embedded, app-owned) Min macOS: 14.0 Sonoma, arm64 only DB: SQLCipher · Keychain-held key MCP: loopback Streamable HTTP + stdio shim Capture: CDP Network/Fetch + DOM evidence, not page-patch primary

Decision in one paragraph

Build a dedicated Electron/Chromium shell that owns its browser sessions end-to-end. Each Arena account lives in its own persistent Electron session.fromPartition; capture is done out-of-band in the browser process via webContents.debugger (Chrome DevTools Protocol: Network + Fetch domains, Target.setAutoAttach for workers/targets) plus session.webRequest metadata and will-download artifact ownership — with a minimal preload DOM bridge only as second evidence for labels, votes, reveals, and branch state. This is materially deeper than the existing Manifest V3 extension baseline (which depends on page-world patching, sees no response bodies without a user-visible debugger banner, and cannot own partitions or downloads). WKWebView-based options (native Swift, Tauri/Wry) are rejected because they cannot observe https response bodies or service-worker traffic without private-API swizzling. CEF is the credible runner-up on raw interception depth but loses on agent-implementability, Node/MCP ergonomics, and maintenance for a private single-operator project; it is the named fallback.

Recommendation Unknowns kept visible No Arena endpoint, payload, or transport is claimed as verified. Every architecture-critical assumption has a falsification test in §10.

Decisive trade-offs (honest costs)

  • One Chromium copy (~200–400 MB on disk, one renderer per active account + GPU/network service). Verified fact Electron embeds Chromium+Node (electronjs.org, releases page consulted). Cost is accepted because the brief forbids duplicated engines and WKWebView cannot deliver bodies; two concurrent accounts ≈ two renderers + shared browser process is the cheapest capable topology. Quotas in §4 cap idle renderers.
  • CDP is still a debugging surface, not a tap. Large-stream buffering, inspector cache eviction (Request content was evicted from inspector cache), and redirect-body gaps are real Chromium behaviors Verified fact (Chromium issues consulted). Mitigation: prefer Fetch response-stage pausing + takeResponseBodyAsStream for conversation hosts only, never whole-web interception; spill to disk; treat eviction as a first-class completeness signal, not silent loss (§5).
  • Some page-world bridging remains. Selected labels, blind labels, vote widgets, reveal timing, and branch/regeneration affordances have no guaranteed network counterpart, so a sandboxed preload observer is required. Difference from the baseline: it is corroboration, never the primary transcript path. If the shell relied primarily on page monkey-patching for network, the brief requires saying so — it does not.
  • Email-auth compatibility preserved; Google/OAuth/passkeys explicitly out of scope as required. Ordinary Chromium presents the normal email flow (address → continue → verification link/code, optional name step) Verified fact (Arena help center article consulted, §2). No masking beyond a standard UA is planned in v1; bot-challenge handling is pause-and-surface, not evasion tooling.

Fallback with trigger (not a menu)

Fallback: CEF (Chromium Embedded Framework) native shell + sidecar services. Trigger if the falsification spike (§10, Gate B) shows concrete, reproduced loss through maintained Electron surfaces that CEF's CefResourceRequestHandler::GetResourceResponseFilter IO-thread filter demonstrably recovers on the same Arena workflows — e.g., systematic inspector-cache eviction on long streams, or worker-frame attribution Electron cannot resolve. Preserved: partitions via RequestContext, downloads via CefDownloadHandler, CDP via remote-debugging port. Lost: Node/MCP ergonomics (must rebuild sync/store/MCP as sidecars), agent build velocity, prebuilt SQLCipher/FTS bindings; C++/CMake maintenance becomes the project's dominant cost. A custom Chromium fork is not authorized unless CEF's public filter + DevTools surfaces also provably fail on a named observation — the brief's last-resort condition.

What “deeper than the window” concretely means in this plan
  • Attach point is the browser process (webContents.debugger + Target), registered before first navigation and re-armed on every web-contents-created / new-popup / worker event — not a content script racing document_start.
  • Bodies come from the network stack (Fetch/Network domains), not from re-reading response.text() in page JS. webRequest is used only for metadata/redirect/auth signals because it provably cannot return bodies.
  • Downloads are owned file writes (will-download → encrypted vault path), not extension downloads + companion stitching.
  • What still depends on the page: reveal/vote timing, blind→revealed label mapping, branch/regeneration affordances, and any canvas-only rendering. That bridge is sandboxed, versioned, and corroborating — §5 states the information lost if it fails.

Process & trust boundaries

  • Arena-controlled content (page, workers, SW, remote scripts) can never reach the archive key, local files, privileged IPC, or the MCP port. Preload exposes a minimal append-only evidence pipe (arena:dom-evidence) + no eval bridge; all parsing/sanitizing happens in main.

Read-verification rule. Sync now semantics (per account or selected accounts)

  • Scope & control: one account or operator-selected set; optional per-account auto-sync (explicitly enabled, off by default). Visible progress (pages, items, bytes, ETA-from-rate), pause / cancel / resume per account and global kill-switch. Cancel leaves checkpoints; resume continues from checkpoint, never from scratch.
  • Isolation: pagination cursors, checkpoints, retries, and dedup markers are namespaced by account_id. Overlapping/repeated pages and pagination instability are expected: dedup key is (account_id, source_conversation_id, revision) — identical text alone never dedups.
  • Concurrency: accounts sync independently; default is sequential across accounts, concurrent within an account's bounded prefetch to avoid cross-account rate-limit entanglement. Parallel multi-account sync is allowed behind a flag after rate behavior is measured, with per-account token buckets.
  • Live-capture overlap: a conversation open live while syncing is reconciled by (source id + revision + completeness): live pending turns are not overwritten by older sync snapshots; sync backfills finalized revisions around them. Conflicts surface as needs-review, never auto-merged across accounts.
  • Degradation: rate-limit (backoff+jitter, per-account), auth expiry (pause that account, surface re-sign-in, others continue), drift/redirect/challenge/suspected mutation (pause that account + snapshot sanitized evidence). Cross-account source-ID collisions → explicit ownership-conflict rows quarantined for operator review.
  • “Synchronized” defined: per account: list coverage (pages walked, cursors exhausted or explicitly bounded), detail coverage (x/y conversations with full revisions), gap list (IDs seen but not retrievable + reason). An agent can inspect all three over MCP. Opening one known conversation proves nothing about full coverage.

If no reliable listing/pagination/complete-detail representation can be verified, the plan stays honest: sync degrades to bounded traversal + live accumulation from now on, gaps are listed, and the archive's coverage statement says so. No silent completeness.

07Data, identity, provenance, protection

Source-of-truth design (proportionate hybrid)

Recommendation Normalized records + retained sanitized observations (bounded) — not full event sourcing. Normalized tables are the query truth; a bounded, encrypted observation store supports reparse after adapter changes; derived indexes/exports are rebuildable and never authoritative.

-- sketch (SQLite/SQLCipher, FTS5). Keys: (account_id, source_*) — never global dedup.

  • Provenance per normalized fact: producing account_id/partition, mechanism (cdp-fetch/cdp-network/websocket/dom/import), adapter/parser version, observed-at, completeness/uncertainty. Sanitized samples retained ~90 days (tunable) then GC'd; normalized facts persist.
  • Transactions/crash: WAL inside encrypted DB; capture write = one TX (observations + normalized upsert + FTS); checkpoint-then-advance for sync; migrations versioned with rollback snapshot; backup = timestamped encrypted copy + key-escrow reminder (Keychain, not in backup); restore verified by hash + coverage recount.
  • Deletion: one conversation (rows + FTS + artifacts + observations for that conv), one account's local data (all rows + partition storage wipe + vault subtree), whole archive (DB + vault + caches + MCP token rotation). Deletion is transactional per scope with failure recovery (idempotent job); future syncs treat deleted source IDs as tombstones (do not silently re-import; surface re-appearance as reappeared-after-delete); external exports/backups are listed as residual — their erasure is never promised.

Model identity (observed vs inferred — never conflated)

  • Preserve: selected label, blind labels, displayed provider/model strings, post-vote reveals with timestamps/turn ranges, and source (ui|network|import|annotation). Position ≠ provider ≠ marketing name ≠ route ≠ build — stored as separate fields.
  • Conflicts/unknowns persist as rows, surfaced in transcripts (blind-unresolved, conflicting-reveal). A later reveal adds a new identity_observation and updates the view; it never rewrites history or extends the label beyond its turn range without evidence.

Archive capabilities & security

  • Offline-first: text search (FTS5) + filters (account, date, mode, observed/revealed model, state, provenance); branch-aware transcripts; versioned machine-readable export (JSON with provenance envelope) + human-readable export (Markdown). Cross-account search allowed; account source always shown; exports scope to one / selected / all accounts without collapsing boundaries.
  • Encryption: DB file fully encrypted (SQLCipher AES-256); key = crypto.randomBytes(32) generated once, held in Keychain, loaded via safeStorage into main memory only. Artifacts: AES-256-GCM files with per-file nonce, key-wrapped by the archive key. FTS index lives inside the encrypted DB (no plaintext sidecar).
  • Plaintext exposure audit: browser storage (partition jars — OS-permissioned, excluded from exports/diagnostics); temp files (vault-staging only, immediate re-encrypt + unlink); logs/crash reports (sanitizer + allow-list fields; journal/WAL inside encrypted container); swap (memory-only key, mlock where available — residual OS risk disclosed); Spotlight (vault + DB directories flagged no-index); Time Machine (encrypted-at-rest blobs only; key never in backup — restore needs Keychain).
  • Secret exclusion: credentials, auth headers, cookies, OAuth codes, CSRF secrets, passwords, signed URLs, unrelated private fields are redacted before persistence or diagnostic emission — including parser-error paths. URLs with secrets are stored as {template, host, hash} (e.g., https://arena.ai/…?s=⟨redacted:sha256:9f…⟩), never raw.
  • Privilege separation re-stated: renderer/preload hold no key, no fs, no MCP token; MCP destructive scope is partition-bound; errors/sign-outs/concurrency preserve isolation (tested in Gate E).

08Full LLM operability — local MCP contract

Transport & trust: loopback Streamable HTTP MCP on 127.0.0.1:<ephemeral> (single MCP endpoint, JSON-RPC), per-install 256-bit bearer token generated at first run and stored in Keychain; Host/Origin allow-list (127.0.0.1/localhost only), DNS-rebind guard (reject foreign Host), no LAN exposure. A stdio shim spawns the same service for clients that only speak spawned-servers. Discovery via standard MCP tools/list + resources/list; unavailable ops return typed UNAVAILABLE_STATE with retry_after / required_state. GUI and MCP call the same service layer — identical semantics, shared state machine; browser-interaction needs (focus/click during email verification) are explicit tools, not hidden GUI-only steps.

State, errors, pagination

  • Jobs: queued → running ⇄ paused → complete | failed | cancelled; cancel is cooperative with checkpoint guarantee; retries bounded with jitter; idempotency keys make re-start safe.
  • Errors (typed): ACCOUNT_MISMATCH, ACCOUNT_SIGNED_OUT, AMBIGUOUS_OWNERSHIP, RATE_LIMITED, DRIFT_PAUSED, CHALLENGE_PENDING, ADAPTER_UNKNOWN, QUOTA_EXCEEDED, UNAVAILABLE_STATE, CONFIRMATION_REQUIRED, FORBIDDEN_CONTENT_PRINCIPAL — each with retryable, retry_after, required_state, affected_account_ids.
  • Pagination: opaque cursors, limit caps, stable ordering (updated_at, conv_id); every list echoes the account_id scope it was evaluated under.

Guard against content-driven destructive actions

Archived content is untrusted data, never authority. Account/archive deletion requires two things from a trusted control channel (the local GUI confirm dialog or an MCP client session presenting the live scope token): (1) the exact scope just shown to the operator (account label + source-ID count + date range), and (2) a fresh single-use scope_token minted by the service plus a typed phrase (e.g., the account label). Retrieved prompts/responses/diagnostics can never supply or satisfy this — the service validates token freshness, channel binding (GUI window or the authenticated MCP bearer session that requested it), and scope equality, and rejects on any mismatch with CONFIRMATION_REQUIRED. Prompt-injection text urging deletion is therefore inert: it lacks the live token and the trusted-channel binding by construction.

09Local analysis & later modalities

Initial model profiles (deterministic first)

Recommendation Group only by observed/revealed identity evidence with uncertainty preserved (blind-position cohorts stay separate from revealed-model cohorts). Start with transparent counts — no black-box scorer in v1:

  • Lengths (response/paragraph/sentence/code-block), lexical diversity, recurring phrases/n-grams, punctuation/casing; Markdown structure (headings/lists/tables/citations/code-vs-prose); openings/transitions/conclusions, hedging/refusal/apology/uncertainty markers — each with per-cohort denominators and linked excerpts → source evidence.
  • Cuts by prompt type/topic/mode/language/time/conversation context where sample supports it; every cut shows n and confidence notes.
Limits of a one-operator corpus. Selection bias (your prompts/topics), prompt/topic confounding, history effects, hidden system prompts, decoding/tools/safety layers, aliases/routing, temporal drift, Arena post-processing, uncertain labels. Supportable: within-corpus stylistic description of observed cohorts. Misleading without controls: cross-model capability ranking or authorship claims. Profiles print their cohort definitions, label provenance, and these caveats on every run.

Embeddings/local ML: deferred. Entry gate (all required): ≥ a measured cohort size with held-out conversations, a frozen preprocessing/tokenizer version, pinned weights with hashes acquirable offline once, and a reproducibility checklist (seed, split, negative controls). Until then the packaging/RAM/reproducibility cost on 18 GB is unjustified. If admitted: weights in vault (hashed, versioned), offline-only inference, per-run provenance.

Later similarity / fingerprinting experiments (hypotheses, not proof)

  • Similarity to the archive is a confidence-qualified hypothesis, never identity proof. Inferred identity lives in analysis_runs, never in identity_observations.
  • Require: leakage-resistant splits (near-duplicate/branch-aware grouping — related branches never split across train/test), held-out conversations, prompt/topic controls, negative + unknown-class handling, calibration, reproducible seeds, and a predeclared continue / revise / abandon rule. No universal sample thresholds are invented here; each experiment predeclares its minimum evidence and stops when results lack scientific utility.

Capture per turn: pending → complete | stopped | failed | partial-observer-gap | partial-navigation | unknown-terminal.
