Private Arena Conversation Archive — capture-first architecture for heavy, multi-account research use

Use Arena normally inside the app. The app watches your own signed-in sessions with browser-privileged (not page-privileged) observation, reconstructs accurate structured transcripts — battle, direct, side-by-side; complete, stopped, failed, partial; branches, revisions, votes, reveals — and keeps them in an encrypted, offline, MCP-operable local archive. 00Decision snapshot

★ Selected: Electron (embedded Chromium) as the dedicated browser, per-account persistent partitions, dual-channel capture (CDP session-level + DOM reconciler), Node application services, SQLCipher archive, local MCP over stdio + loopback HTTP.

The single decisive reason: Electron is the only mainstream, maintained, Apple-Silicon-native embedding that simultaneously (a) owns full Chromium session state per account, (b) exposes browser-process network/target/session APIs (CDP via webContents.debugger + session.webRequest + partition-scoped downloads/cookies/storage/service-workers) far beyond what page-world injection or an extension content script can see, (c) runs Arena's ordinary email sign-in (including OTP/MFA/CAPTCHA/popups/redirects) as a real browser with no third-party-IdP embedding penalty, and (d) stays maintainable by AI agents (one runtime, TypeScript throughout, mature docs) without a custom Chromium fork or a second browser engine.

✓ What the winner owns that the extension never can

  • Session-level network view: CDP Network / Fetch / WebSocket / ServiceWorker / Target domains attached from the main process, auto-attached to iframes/workers/service-workers — not injected into a page that may not exist yet.
  • Early-attach & lifecycle control: attach before navigation commits, observe target creation/destruction, gate navigation until observers are armed.
  • True account partitions: session.fromPartition('persist:arena-acct-<id>') isolates cookies, storage, cache, service-workers, and capture pipelines per account in one engine.
  • Direct artifact path: will-download + save-dialog ownership → application-owned files, no extension download bridge or companion program.

⚠ Honest limit (stated up front)

A dedicated shell still needs a small page-world preload (isolated world, contextBridge) as a reconciler for rendered text, vote/reveal DOM events, and stream-tail repair. The difference: network truth comes from browser privilege; the DOM is corroboration, not the primary capture path. Any claim that “embedded = automatically deeper” without naming the CDP/session APIs is rejected in §4–§5.

Reversal conditions fallback has a trigger, not a vibe

  • Trigger R1 — CDP cannot see Arena’s conversation bodies/streams reliably (spike shows systematic misses vs DOM across transports): escalate to a scoped loopback-proxy capture bound to the app’s partitions (still app-owned, still no extension), then to CEF only if proxy + CDP both fail on a named observation. Preserved: partitions, MCP, archive. Lost: Electron’s packaging simplicity; CEF adds ~170 MB, helper processes, manual lifecycle.
  • Trigger R2 — Electron resource ceiling breached (2-account heavy use exceeds resident budget on 18 GB with evidence): freeze second renderer (single visible window + hidden partition windows), then consider CEF’s finer process control. Preserved: capture semantics. Lost: simultaneous-visible-windows UX.
  • Trigger R3 — Arena e-mail flow breaks under Electron (persistent CAPTCHA/MFA loops attributable to the client, not the account): allow a system-browser handoff for the login ceremony only, importing nothing but the resulting app-partition session via Arena’s own Set-Cookie flow inside the app — never cookie/token import from other browsers. Preserved: capture. Lost: pure in-app onboarding.
  • Mention of a custom Chromium fork is a last-resort escalation only, gated on a concrete observation impossible through CDP + proxy + CEF public surfaces. It is not planned, staffed, or budgeted in v1.

Baseline to beat (not to pick)

Known baseline: musterm4nn-alt/arena-exporter (Manifest V3 extension) — rejected as target

Useful, but structurally capped: service-worker lifecycle eviction loses streams; content-script injection timing misses early navigation/worker traffic; no response-body APIs in webRequest/declarativeNetRequest (bodies need page-world fetch patching — fragile, page-visible, race-prone); chrome.debugger-as-extension shows a banner, detaches, single-target; downloads go through the extension downloads API + companion bridge awkwardness. §3 enumerates each cap with the dedicated-browser mechanism that removes it. Improving that extension via chrome.debugger/native-messaging is explicitly a different project and is not this plan.

Scope boundaries (owner-session ethics, technical form)

  • Only data associated with currently signed-in, app-owned Arena sessions; every operation bound to its account/partition. A URL or opaque ID never establishes ownership.
  • No enumeration of unrelated infra, credential guessing/theft, or cookie/token import from other browsers/apps. No cross-account merges on similar text/IDs/titles/timestamps.
  • Native sync code may transiently reuse credentials issued to the correct app-owned session (including refresh) but must never persist them to disk, exports, fixtures, or logs. Browser-managed session persistence (partitioned cookies/storage) is separate, Keychain/OS-protected, per-partition.
  • Recording/automation exposes visible per-account + global pause / cancel / stop with defined in-flight semantics (§7, §10).
  • On sign-out, mismatch, authority loss, or ambiguous ownership: stop or degrade only the affected account; never invalidate, corrupt, or silently rebind the other. Unsupported navigation, observer failure, drift, rate limits, challenges, unexpected redirects, or suspected mutation → pause or documented fallback for that account.
  • Arena ToS/privacy documents are out of planning scope by instruction; methods are judged on feasibility, security, robustness, maintainability. Legal judgment is the owner’s.

⚠ Terminology the plan enforces

Authenticated read access = first-party endpoints called with the correct account-scoped session (undocumented ≠ bypass). Automation compatibility = normal browser presentation, automation-signal hygiene, challenge handling. Access-control workaround = defeating a client-side control to reach your own accounts’ data — must name the control, mechanism, ownership evidence, binding, failure mode, and maintenance cost. “Bypass” is never used as a loose synonym for “internal API”.

Verdicts (fair treatment, then concentration)

  • Native Swift + WKWebView — rejected. Beautiful citizen, blind observer. Verified fact No http/https body interception; Safari-Inspector protocol, not CDP; service-worker/cache partitioning is manual. Email auth likely renders, but capture completeness — the #1 priority — is structurally capped. Owning a WKWebView is the textbook case of “window without privilege.”
  • Tauri / Wry — rejected. Same macOS capture ceiling (it is WKWebView on macOS) plus a second-language runtime and no maintained body-interception story. Its capability-ACL security model is admirable and irrelevant if the primary evidence never arrives.
  • MV3 extension + native companion — rejected as target (baseline). It is the tried system. chrome.debugger-as-extension adds a banner, detach races, and single-target limits; native-messaging fixes downloads, not observation depth. Choosing it again would re-buy the exact failure modes this project exists to escape.
  • Export/import without embedded browser — fallback only. Honest, offline-friendly, zero-capture-risk — and zero live capture, zero stream/reveal fidelity, total dependence on whatever export Arena may or may not offer. Kept as the backfill complement (§7), never the primary path.
  • Finalists: Electron vs CEF. Both clear the capture bar in principle. Decided in §4 on packaging, maintenance, and agent-operability — with CEF retained as the named escalation under Trigger R1.

Why page-world monkey-patching is disqualified as a primary path

Patching fetch/XHR/WebSocket from an injected script observes only what runs after injection, in that world, in that frame — missing early navigation, workers, service-workers, and any transport the patch didn’t anticipate, while advertising the observer to the page. The selected architecture inverts this: CDP/session observation is primary; the isolated-world preload is a labeled reconciler, and diagnostics must report which channel each byte came from.

5.2 Process & trust boundaries

Figure 5-1 — Trust topology. Observation flows up (CDP + sanitized reconciler events); control flows down (AppService → windows/jobs). There is no path from Arena content to the archive key, local files, privileged APIs, or the MCP server. Destructive scope is bound to the partition that owns the window.
  • Process split: Electron main (orchestration, CDP sessions, partitions, downloads) · per-account renderer (Arena content, nodeIntegration:false, contextIsolation:true, sandbox:true) · isolated-world preload (DOM reconciler via contextBridge, allowlisted channels only) · utilityProcess workers (sync, parse, analysis — crash-isolated, restartable).
  • Arena-content hardening: no Node in Arena renderers; preload exposes ≤4 functions (reportDomSnapshot / reportRevealEvent / reportStreamTail / ping); Content-Security-Policy owned by app shell; custom protocol allowlist; will-attach-webview / new-window / setWindowOpenHandler denied except owner-driven auth popups (which open as app-owned, partitioned children, never shell.openExternal mid-flow).
  • Secret rule: credentials/headers/cookies/tokens/CSRF/signed URLs are observable transiently by capture code and killed at the sanitizer; only allowlisted conversation/identity/provenance fields persist. Parser errors follow the same path (never dump raw bodies into logs).

5.4 Why this stack (one paragraph per decisive trade-off)

  • Capture reliability over bundle lightness. Tauri/WKWebView saves ~100 MB and a runtime — and forfeits the transcript. For a private research archive on an 18 GB M3 Pro, completeness dominates megabytes. Electron’s single shared Chromium serves both accounts; no duplicated engines.
  • Maintenance over maximal depth. CEF can see marginally more (request-handler granularity) at the price of C++ surface, helper processes, and agent-unfriendly churn. Electron’s CDP covers the known surface (text/streams/votes/reveals/artifacts); the residual is named, tested, and escalated — not hand-waved.
  • Email-auth fidelity without IdP tax. Because only Arena email sign-in is required, the plan banks full-Chromium compatibility (OTP/MFA/CAPTCHA/popups/redirects as ordinary web flows) and refuses to pay WKWebView-workaround or external-handoff complexity in v1.
  • Agent-operability over cleverness. TypeScript end-to-end, one package manager, structured diagnostics, machine-checkable gates, MCP-first. A dependency an agent cannot install, pin, or diagnose is a vetoed dependency.

6.4 Reconstruction: streams → turns → branches (with reconnects, late reveals, navigation)

  • Keys: requestId (wire) → streamId (logical response) → (conversation, branch, turnIndex, participantPosition). Deltas append by sequence; reconnects resume by stream cursor when the protocol offers one, else mark resumed-gap-possible and repair from DOM tail with via: dom-repair provenance.
  • Boundaries: turn open on send/commit; turn close on finish/stop/error/navigation; branch fork on regenerate/edit-resend when observable; revision chains preserved (never overwritten).
  • Late reveals: vote → reveal events update the identity view over the recorded turn range; original blind labels retained (§8). Navigation mid-stream → freeze partial with navigation-interrupted; re-opened conversation reconciles network + UI evidence rather than duplicating.
  • Account binding: every observation tagged (accountId, partition, cdpSessionId, adapterVersion, observedAt) at ingest; pipelines are per-partition singletons so a burst in A cannot interleave into B.

What “verified read” requires before replay is trusted

  • Owner-session evidence: same call, same partition, repeated → identical server state (no new IDs, no vote/title/timestamp side effects; UI cross-check clean).
  • Effective read behavior documented per op: pagination cursor semantics, ordering stability, detail completeness vs list, auth-expiry/challenge behavior, rate-limit signals.
  • Method/endpoint name alone proves nothing; one opened conversation proves nothing about full coverage.
  • If verification fails, the op stays read-unverified and sync uses traversal — the catalog records why.

Sync job contract (per account, resumable, cancellable)

queued → runningcheckpoint load; live-capture handshake (shared conversation locks)

running ⇄ pauseduser/agent pause; in-flight page finishes, no new pages
→

  • Scope: Sync now for one account or selected accounts; opt-in auto-sync per account (off by default; interval + quiet-hours + “pause while I’m actively chatting” heuristics).
  • Progress (visible per account + global): pages done/total-est, items new/updated/skipped, bytes, ETA, current op + adapter version, last checkpoint id, retry budget remaining.
  • Correctness rules: per-account checkpoint isolation; overlapping/repeated pages deduped by (accountId, sourceId, detailHash) — never by text alone; pagination instability handled by cursor-replay + windowed re-fetch, not by assuming monotonic pages; re-runs are idempotent (same evidence → same records + a “re-observed” provenance tick).
  • Concurrency: accounts sync concurrently by default (independent schedulers, per-partition CDP/network budgets); if the box or Arena throttles, the scheduler serializes detail fetches while keeping checkpoints independent — correctness never depends on parallelism.
  • Live-capture overlap: a conversation open in both paths is locked by (accountId, sourceConversationId); live deltas win for the tail, backfill wins for the head; merge is a reconciled projection, both provenances kept.
  • Degradation (affected account only): rate-limit → exponential backoff + budget display; auth expiry → pause + re-login prompt; drift/redirect/challenge → pause + diagnostic bundle; suspected mutation → halt that account’s sync, preserve evidence, never auto-retry a mutating op.
  • Cross-account collisions: same source ID under two accounts = explicit ownership-conflict records on both sides, linked for inspection, never merged.
  • “Synchronized” means, per account: listing cursor at end + all detail fetches resolved + gaps enumerated + receipt signed (op versions, counts, hashes). Anything less is “synced with known gaps,” and the gaps are MCP-inspectable.

  • Exports: versioned machine-readable (JSONL + manifest + provenance bundle + hashes) and human-readable (Markdown/PDF-via-print); scope picker: one account / selected / all — account source stamped on every record, boundaries never collapsed.

11.3 Similarity / fingerprinting experiments (later, heavily conditioned)

  • Similarity to an archived corpus is an unverified, confidence-qualified hypothesis — never proof of identity/authorship. Inferred identity lives in a separate namespace from observed identity, always.
  • Predeclared protocol: leakage-resistant splits at the conversation level with branch grouping (related branches never span train/test); held-out conversations; prompt/topic controls; negative controls (known-different identities); calibration; unknown-class handling; reproducible seeds + manifests; empirically justified minimum evidence (no universal thresholds invented — minimums are estimated from the corpus and reported).
  • Continue / revise / abandon: continue only on held-out + control success with calibration; revise on confound-dominated results (re-cut cohorts); abandon when results lack scientific utility after predeclared budget — recorded as a finding, not a failure.
